# Step 002 — Errors module

## Goal

Provide the single source of truth for exit codes, `kind` strings, the `CodeIndexError` exception type, the JSON error envelope writer, the stderr summary formatter, and the stream-discipline helpers that every subcommand uses to write output. No subcommand-specific logic lives here; this module is consumed by config (003), storage (004), and CLI (005).

## Files to create or modify

- `src/code_index/errors.py` (new)
- `tests/test_errors.py` (new)

## Signatures

```python
# src/code_index/errors.py

# Exit-code integer constants. One per row in errors-and-exit-codes.md's table.
EXIT_OK: int = 0
EXIT_USAGE: int = 1
EXIT_CONFIG: int = 2
EXIT_INDEX_SCHEMA: int = 10
EXIT_INDEX_MODEL: int = 11
EXIT_INDEX_MISSING: int = 12
EXIT_BACKEND: int = 20
EXIT_BACKEND_AUTH: int = 21
EXIT_BACKEND_RATE_LIMIT: int = 22
EXIT_PARSING_PLUGIN: int = 30
EXIT_IO: int = 40
EXIT_IO_OVERSIZE: int = 41
EXIT_UNKNOWN: int = 99

# kind registry — string constants grouped by category. One per row in the
# "Enumerated failure surface" section of errors-and-exit-codes.md, PLUS the
# new "cli.not_implemented" added by this feature.
class Kinds:
    CLI_NOT_IMPLEMENTED: str = "cli.not_implemented"
    CONFIG_PARSE_ERROR: str = "config.parse_error"
    CONFIG_MISSING_KEY: str = "config.missing_key"
    CONFIG_VERSION_MISMATCH: str = "config.version_mismatch"
    CONFIG_BAD_ENUM: str = "config.bad_enum"
    CONFIG_MODEL_BACKEND_MISMATCH: str = "config.model_backend_mismatch"
    CONFIG_BAD_PATH: str = "config.bad_path"
    CONFIG_UNKNOWN_LANGUAGE: str = "config.unknown_language"
    INDEX_VEC_EXTENSION_UNAVAILABLE: str = "index.vec_extension_unavailable"
    INDEX_FTS5_UNAVAILABLE: str = "index.fts5_unavailable"
    INDEX_SCHEMA_MISMATCH: str = "index.schema_mismatch"
    INDEX_MISSING: str = "index.missing"
    INDEX_UNREADABLE: str = "index.unreadable"
    INDEX_EMBED_DIM_MISMATCH: str = "index.embed_dim_mismatch"
    INDEX_EMBED_MODEL_MISMATCH: str = "index.embed_model_mismatch"
    # backend.* / parsing.* / io.* are listed here too for the full registry,
    # even though only config + index + cli kinds are raised in Phase 1.

class CodeIndexError(Exception):
    code: int
    kind: str
    message: str
    detail: dict[str, object] | None

    def __init__(
        self,
        code: int,
        kind: str,
        message: str,
        detail: dict[str, object] | None = None,
    ) -> None: ...

    def envelope(self) -> dict[str, object]:
        """Return the JSON envelope dict (matches errors-and-exit-codes.md)."""

# Output stream helpers — the only sanctioned writers in the codebase.

def write_result_stdout(payload: str) -> None:
    """Write a successful result to stdout. Adds trailing newline if missing."""

def write_log_stderr(message: str) -> None:
    """Write a human log/warning/progress line to stderr."""

def write_error_envelope_stdout(err: CodeIndexError) -> None:
    """Write the JSON error envelope to stdout under --format json."""

def write_error_summary_stderr(err: CodeIndexError) -> None:
    """Write a single-line human summary to stderr under --format text.
    Optional follow-up detail lines if detail is non-empty."""
```

The envelope shape is:

```json
{
  "error": {
    "code": <int>,
    "kind": "<dotted-string>",
    "message": "<one line>",
    "detail": { ... } | null
  }
}
```

## Tests

`tests/test_errors.py`:

- `test_envelope_shape`: a `CodeIndexError(2, Kinds.CONFIG_VERSION_MISMATCH, "msg", {"pin": ">=0.3,<0.5"})` produces an envelope whose keys are exactly `{"error"}`, and `error` has keys `{"code", "kind", "message", "detail"}` with values matching the inputs.
- `test_envelope_detail_optional`: detail omitted yields `"detail": None` (or missing — coder picks, but document the choice via the test).
- `test_envelope_writer_uses_stdout`: capturing stdout via `capsys`, `write_error_envelope_stdout(err)` writes a JSON document that `json.loads` round-trips to the expected dict and writes nothing to stderr.
- `test_summary_writer_uses_stderr`: `write_error_summary_stderr(err)` writes one line containing the message to stderr and nothing to stdout.
- `test_result_writer_uses_stdout`: `write_result_stdout("hello\n")` writes to stdout, not stderr.
- `test_log_writer_uses_stderr`: `write_log_stderr("walking ...")` writes to stderr, not stdout.
- `test_exit_codes_match_contract`: every constant matches the exit-code table values in `errors-and-exit-codes.md` (`0, 1, 2, 10, 11, 12, 20, 21, 22, 30, 40, 41, 99`).
- `test_kinds_match_contract`: every `Kinds.*` value is exactly the dotted string named in `errors-and-exit-codes.md` (one assertion per kind).

## Definition of done

- All exit-code integer constants present and match the table in `errors-and-exit-codes.md`.
- `Kinds` registry covers every dotted string named in the "Enumerated failure surface" section of `errors-and-exit-codes.md`, plus the new `cli.not_implemented`.
- `CodeIndexError` has `code`, `kind`, `message`, `detail` attributes and an `envelope()` method.
- Envelope writer writes exactly one JSON document to stdout, with `json.loads` round-tripping cleanly.
- Summary writer writes a single line to stderr.
- Stream helpers do not cross-talk (stdout helper does not touch stderr and vice versa).
- `uv run pytest tests/test_errors.py` passes.
- `uv run pyright` passes for `src/code_index/errors.py`.
- `uv run ruff check` passes.
