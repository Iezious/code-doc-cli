# Step 003 — Config loader

## Goal

Implement the per-project config loader: parse TOML at `docs/.helpers/config.toml` (or the path given via `--config`), validate against the schema in [`../../architecture/config.md`](../../architecture/config.md), apply defaults, and return a resolved config object. Every validation failure maps to the correct `code` / `kind` from the Config section of [`../../architecture/errors-and-exit-codes.md`](../../architecture/errors-and-exit-codes.md).

## Signatures

```python
# src/code_index/config.py

from pathlib import Path
from pydantic import BaseModel

EmbedBackend = Literal["fastembed", "voyage"]

class CodeIndexConfig(BaseModel):
    version: str                          # PEP 440 specifier, required
    project: str                          # defaulted to parent dir name at load time
    roots: list[str]                      # default ["."]
    ignores: list[str]                    # default []
    languages: list[str]                  # default = all seven built-in names
    extra_languages: list[str]            # default []
    embed_backend: EmbedBackend           # default "fastembed"
    embed_model: str                      # default depends on backend
    embed_batch_size: int                 # default 32

DEFAULT_LANGUAGES: tuple[str, ...] = (
    "fsharp", "csharp", "javascript", "typescript", "go", "python", "lsl",
)

ALLOWED_BACKENDS: tuple[str, ...] = ("fastembed", "voyage")

BACKEND_DEFAULT_MODEL: dict[str, str] = {
    "fastembed": "jinaai/jina-embeddings-v2-base-code",
    "voyage": "voyage-code-3",
}

def load_config(
    config_path: Path,
    *,
    project_root: Path | None = None,
    engine_version: str | None = None,
) -> CodeIndexConfig:
    """Parse, validate, and resolve the config.

    project_root is the directory containing docs/.helpers/. Defaults derived
    from config_path: project_root = config_path.parent.parent.parent
    (config.toml -> .helpers -> docs -> project).

    engine_version defaults to code_index.__version__; injectable for tests.

    Raises CodeIndexError for every documented failure mode.
    """

def discover_config_path(start: Path) -> Path:
    """Walk upward from `start` looking for `docs/.helpers/config.toml`.

    Returns the resolved path. Raises CodeIndexError(EXIT_INDEX_MISSING,
    Kinds.INDEX_MISSING, ...) when none found — wait, that is the index
    file's failure, not config. For config discovery failure raise
    CodeIndexError(EXIT_CONFIG, Kinds.CONFIG_PARSE_ERROR, ...) — actually
    the right kind for 'config file not found' is open. See step context.
    """
```

> **Open at planning time, settled here:** the `kind` for "config file not found via upward walk" is not enumerated in `errors-and-exit-codes.md`. The CLI scaffold step (005) is what triggers discovery; this step exposes `discover_config_path` and the loader, and lets failures propagate as `CodeIndexError`. The mapping decision for "no config found" is recorded in step 005's context, **not** here. This step's tests therefore only exercise `load_config(config_path)` with an explicit path — discovery is tested in step 005.

## Validation rules (one-to-one with `errors-and-exit-codes.md` Config section)

| Failure | Exit code | Kind |
|---|---|---|
| Malformed TOML | 2 | `config.parse_error` |
| Missing required key (`version`) | 2 | `config.missing_key` |
| Version pin unsatisfied by `engine_version` | 2 | `config.version_mismatch` |
| `embed_backend` not in allowed values | 2 | `config.bad_enum` |
| `embed_model` incompatible with backend | 2 | `config.model_backend_mismatch` |
| `roots` path missing / not resolvable under project root | 2 | `config.bad_path` |
| `extra_languages` path missing / unreadable | 2 | `config.bad_path` |
| `languages` name not registered | 2 | `config.unknown_language` |
| Unknown key under `[code_index]` | 0 | (warning on stderr only) |

For Phase 1 the "registered language names" set is `DEFAULT_LANGUAGES` plus the basenames of `extra_languages` files (the plugin registry from Phase 3 will own the real set; this step approximates it via the built-in names, which is enough to make `config.unknown_language` testable). Document this approximation in the docstring.

`embed_model` / backend compatibility for Phase 1: only the defaults from `BACKEND_DEFAULT_MODEL` are accepted as a "known good" pair. Any other combination is treated as compatible (no whitelist) — the real compatibility check belongs to Phase 2 backends. The `config.model_backend_mismatch` kind is therefore only raised in Phase 1 if a backend reports itself unable to instantiate, which it cannot do yet; the kind is still registered (step 002) and the loader has the plumbing in place so Phase 2 can wire the check. Tests assert that the **default** model for each backend passes.

PEP 440 specifier parsing uses `packaging.specifiers.SpecifierSet` from the `packaging` library (already a transitive dep via pip's universe; add to `[project.dependencies]` if not already pulled in by Pydantic).

## Tests

`tests/test_config.py`:

- `test_valid_config_loads`: load `tests/fixtures/config_valid.toml` with a matching `engine_version`. Returns a `CodeIndexConfig` with the expected values, defaults applied.
- `test_defaults_applied`: a minimal config (only `version`) yields defaults for `roots`, `ignores`, `languages`, `embed_backend`, `embed_model`, `embed_batch_size`.
- `test_project_default_is_dirname`: `project` not in TOML → falls back to `project_root.name`.
- `test_embed_model_default_per_backend`: omitting `embed_model` with `embed_backend = "voyage"` yields `"voyage-code-3"`; with `"fastembed"` yields `"jinaai/jina-embeddings-v2-base-code"`.
- `test_malformed_toml_raises`: `config_malformed.toml` → `CodeIndexError(code=2, kind="config.parse_error")`.
- `test_missing_version_raises`: `config_missing_version.toml` → `kind="config.missing_key"`.
- `test_version_mismatch_raises`: `config_version_mismatch.toml` pins `">=99.0"` and `engine_version="0.1.0"` → `kind="config.version_mismatch"`. `detail` contains `pin` and `engine_version`.
- `test_bad_enum_raises`: `embed_backend = "nope"` → `kind="config.bad_enum"`.
- `test_bad_path_roots_raises`: `roots = ["./does-not-exist"]` → `kind="config.bad_path"`.
- `test_bad_path_extra_languages_raises`: `extra_languages` pointing at a non-existent file → `kind="config.bad_path"`.
- `test_unknown_language_raises`: `languages = ["klingon"]` → `kind="config.unknown_language"`.
- `test_unknown_key_warns_not_raises` (capsys): unknown key under `[code_index]` does not raise; a warning is written to stderr containing the unknown key name; exit code is irrelevant (loader returns successfully).

Each fixture file must be minimal and contain a comment naming the failure mode it exercises.

## Definition of done

- `load_config` accepts a `Path` and returns a `CodeIndexConfig`.
- Every row in the validation table above is exercised by exactly one test and produces exactly the documented `code` and `kind`.
- Defaults match `config.md`'s table.
- `embed_model` defaults are picked from `BACKEND_DEFAULT_MODEL` based on the active `embed_backend`.
- PEP 440 specifier parsing uses `packaging.specifiers`.
- Unknown keys produce a stderr warning via `write_log_stderr`, not a raise.
- `uv run pytest tests/test_config.py` passes.
- `uv run pyright` passes.
- `uv run ruff check` passes.
- No `print()` calls — only `errors.write_log_stderr` is used for the unknown-key warning.
