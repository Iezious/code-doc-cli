# 005 — CLI scaffold and `config show`

## Goal

Build the Typer CLI: every MVP subcommand from [`../../architecture/cli.md`](../../architecture/cli.md) is registered (most as stubs raising `cli.not_implemented`), shared flags `--config`, `--format`, `--verbose`, `--quiet` are wired at the app level, `CodeIndexError` is caught at the boundary and routed through the envelope writer, and `config show` is implemented end-to-end: discover the config (or honor `--config`), validate it, print resolved values to stdout. This step also delivers the Phase 1 DoD tests.

`cli_config_show` behavior:

1. Resolve the config path: `ctx.obj["config"]` if set, else `discover_config()` from CWD; if neither yields a path, raise `CodeIndexError(code=2, kind="config.missing_key", message="no docs/.helpers/config.toml found; run `code_index init`")` — coder may use `kind="config.missing_key"` or invent a new `kind` like `"config.not_found"`; since there is no doc entry for "not found", reuse `index.missing` (code 12) per `errors-and-exit-codes.md` "Index file missing where one is required" is the closest existing match. Use `index.missing` with a clarifying message.
2. Call `load_config(path)`. On `CodeIndexError`, re-raise (boundary handler catches).
3. Print resolved values:
   - Default (`--format text`): one `key = value` per line, sorted by key, to stdout via `write_result_stdout`.
   - `--format json`: a single JSON document with the full resolved config to stdout via `write_json_stdout`. Stable shape — record it as part of the JSON contract noted in `outcome.md`.

Boundary exception handler:

```python
# Registered on the Typer app (e.g. via a try/except wrapper in __main__ or via
# typer.Exit + a custom result_callback). On CodeIndexError:
#   - if format == "json": write_error_envelope_stdout(err); also one-line summary to stderr
#   - else: write_error_stderr_summary(err) only
#   - raise typer.Exit(err.code)
# On any other unhandled exception: code=99, kind="unknown".
```

## Tests

`tests/test_cli.py` uses `typer.testing.CliRunner`. The Phase 1 DoD is asserted here.

DoD-1: `code_index --help` lists every MVP subcommand:

- Help output mentions `init`, `index`, `search`, `symbols`, `graph`, `config`.
- `code_index index --help` mentions `build`, `sync`, `rebuild`.
- `code_index symbols --help` mentions `defs`, `refs`.
- `code_index graph --help` mentions `callers`, `deps`.
- `code_index config --help` mentions `show`.

DoD-2: `code_index config show --config <fixture>` against `tests/fixtures/config_valid.toml`:

- Exit code 0.
- stdout contains the expected resolved values (`embed_backend`, `embed_model`, etc.).
- stderr is empty (no warnings for the valid fixture).

DoD-3: Each Config-row in `errors-and-exit-codes.md` produces the right exit code and `kind` under `--format json`. For each fixture from step 003:

- Run `code_index config show --config <fixture> --format json`.
- Exit code matches `code` from the doc.
- stdout parses as JSON; envelope `error.code` and `error.kind` match the expected values from the doc.

DoD-4: Each stub (`init`, `index build`, `index sync`, `index rebuild`, `search foo`, `symbols defs foo`, `symbols refs foo`, `graph callers foo`, `graph deps foo`) exits with code 1 and, under `--format json`, prints an envelope with `kind = "cli.not_implemented"`.

DoD-5: Unhandled exception path. Construct a config fixture that raises a non-`CodeIndexError` from inside the loader (e.g. by passing `--config` to a directory rather than a file — pick a path that produces an `OSError`). Exit code is 99; under `--format json`, envelope `kind` is a synthesized `unknown.*` or simply `unknown`. Acceptable kind strings: `"unknown"` or `"unknown.exception"`; pick one and document in code. Test asserts the chosen string.

DoD-6: Stream discipline. `code_index config show --config <valid fixture>` puts the result on stdout and nothing on stderr; `code_index config show --config <broken fixture>` puts the summary on stderr and (under `--format json`) the envelope on stdout.

DoD-7: `python -m code_index --help` matches `code_index --help` (after `__main__.py` is wired). Run via `subprocess.run([sys.executable, "-m", "code_index", "--help"])`.
