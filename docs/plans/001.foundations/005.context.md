## Shared flags

Per [`../../architecture/cli.md`](../../architecture/cli.md) "Cross-cutting behaviors" and "Output streams and logging":

- `--config <path>` — overrides config discovery; available on every subcommand (wire at the app level).
- `--format text|json` — default `text`. Per `errors-and-exit-codes.md`, `--format json` puts results (or error envelopes) on stdout.
- `--verbose` — adds timings and pool sizes to stderr; in Phase 1, only `config show` has anything to log, and that is minimal. Wire the flag but minimal behavior is acceptable.
- `--quiet` — suppresses stderr progress; does not change stdout shape. Wire the flag.

Stub subcommands do not need to accept their final flag set (those flags appear when each phase implements its subcommand). It is enough that the stub registers with the right name; flag definitions can be limited to what's required for `--help` text to be informative. Coder's call on how much flag scaffolding to include in stubs.

## Boundary exception handler shape

Typer supports a `result_callback` on the app for post-invocation hooks, but exception handling is cleanest via a wrapping `try/except` in `__main__.main()` and/or by registering a small wrapper that catches `CodeIndexError` and `Exception`. Both shapes are acceptable.

Behavior on catch:

| Exception | Stream behavior | Exit |
|---|---|---|
| `CodeIndexError`, `--format text` | `write_error_stderr_summary(err)` only | `err.code` |
| `CodeIndexError`, `--format json` | `write_error_envelope_stdout(err)` + `write_error_stderr_summary(err)` | `err.code` |
| `typer.Exit` / `typer.Abort` | Typer's own handling (no override needed) | as set by Typer |
| Any other `Exception`, `--format text` | one-line stderr summary mentioning `kind="unknown"` | `99` |
| Any other `Exception`, `--format json` | envelope with `code=99`, `kind="unknown"` (or `"unknown.exception"`) on stdout; one-line stderr summary | `99` |

The handler must not re-raise after writing; it must call `sys.exit(code)` / `raise typer.Exit(code)`.
