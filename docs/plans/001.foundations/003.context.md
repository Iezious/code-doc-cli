## Pydantic v2 usage

The user decided Pydantic v2 (recorded in [`context.md`](context.md), decision 1). Patterns the coder may choose between:

1. **Field validators raising `CodeIndexError` directly.** Validators run inside Pydantic's machinery and raise the typed error. The loader does not wrap calls in a `try/except ValidationError`.
2. **Catching `ValidationError` at the loader boundary** and translating into `CodeIndexError`. Validators raise `ValueError` with a stable tag (a dict in `ctx`, or a parsed message) so the translator picks the right `kind`.

Either is fine. The DoD checks the externally visible behavior — the right `code`/`kind` reaches the caller — so the internal style is the coder's call.

## Loader sequencing (informational, not prescriptive)

A workable order is:

1. Open file → if missing, `CodeIndexError(EXIT_CONFIG, Kinds.CONFIG_PARSE_ERROR, ...)`. (The "file not found" case is settled in step 005's context — this step's tests only call with an explicit existing path or a parse-fail fixture, so the loader's behavior on missing files is not covered here.)
2. `tomllib.loads()` → `config.parse_error` on TOMLDecodeError.
3. Extract `[code_index]` table → `config.missing_key` if absent or if `version` is absent.
4. Build `CodeIndexConfig` via Pydantic → translate validation errors to the right `kind`.
5. Check engine version against `version` pin → `config.version_mismatch`.
6. Validate `roots` and `extra_languages` paths exist on disk → `config.bad_path`.
7. Validate `languages` against `DEFAULT_LANGUAGES` ∪ basenames of `extra_languages` → `config.unknown_language`.
8. Apply defaults that depend on `embed_backend` (the `embed_model` per-backend default).
9. Warn on unknown keys via `errors.write_log_stderr`.

## Fixture conventions

Fixture files live at `tests/fixtures/config_*.toml`. Each fixture must:

- Have a top comment naming the failure it exercises (or `# valid config` for the passing case).
- Be minimal — only the keys needed to trigger the case.

## What this step does NOT cover

- `discover_config_path` is declared with a signature but the "no config found" failure mode is not tested here. Step 005 owns that test path.
- Compatibility checks between `embed_model` and a real backend instance. Phase 2 introduces backends; for now the kind is registered but only the default-pair case is exercised.
- The full plugin registry. We approximate with `DEFAULT_LANGUAGES` ∪ basenames of `extra_languages`. Phase 3 replaces this with the real registry.
