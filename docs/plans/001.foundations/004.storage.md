## Signatures

```python
# src/code_index/storage/__init__.py

import sqlite3
from pathlib import Path

CURRENT_SCHEMA_VERSION: str = "1"

def open_index(
    db_path: Path,
    *,
    create_if_missing: bool = True,
    check_version: bool = True,
) -> sqlite3.Connection:
    """Open the index at db_path.

    Behavior:
    - Opens the sqlite3 connection.
    - Sets PRAGMA journal_mode = WAL.
    - Enables extension loading and loads sqlite-vec; failure ->
      CodeIndexError(EXIT_INDEX_SCHEMA, Kinds.INDEX_VEC_EXTENSION_UNAVAILABLE).
    - Confirms FTS5 is available (SELECT fts5(?) or sqlite_compileoption_used);
      failure -> CodeIndexError(EXIT_INDEX_SCHEMA, Kinds.INDEX_FTS5_UNAVAILABLE).
    - If create_if_missing and the file did not exist, runs all migrations
      from "0" to CURRENT_SCHEMA_VERSION; writes meta.code_index_version.
    - If check_version and a meta row exists with a different schema_version,
      raises CodeIndexError(EXIT_INDEX_SCHEMA, Kinds.INDEX_SCHEMA_MISMATCH).
    - Returns the connection.
    """

def get_meta(conn: sqlite3.Connection, key: str) -> str | None: ...
def set_meta(conn: sqlite3.Connection, key: str, value: str) -> None: ...
```

```python
# src/code_index/storage/migrations/__init__.py

import sqlite3
from typing import Protocol

class Migration(Protocol):
    from_version: str
    to_version: str
    def apply(self, conn: sqlite3.Connection) -> None: ...

def discover_migrations() -> list[Migration]:
    """Find every <from>_to_<to>.py in this package and return them sorted
    numerically by from_version."""

def run_migrations(
    conn: sqlite3.Connection,
    target_version: str,
) -> None:
    """Walk migrations starting from the current meta.schema_version (or '0'
    if the meta row is absent), applying each in order until meta.schema_version
    == target_version. Wraps each migration in its own transaction. Updates
    meta.schema_version after each successful apply."""
```

```python
# src/code_index/storage/migrations/0_to_1.py

from_version: str = "0"
to_version: str = "1"

def apply(conn: sqlite3.Connection) -> None:
    """Create every table, index, FTS5 virtual table, and vec0 virtual table
    from the schema sketch in storage.md. Set meta.schema_version = '1' and
    meta.code_index_version = code_index.__version__."""
```

Schema to create in `apply` (per [`../../architecture/storage.md`](../../architecture/storage.md), "Schema sketch"). `0_to_1.py` creates **six tables** (plus the FTS5 and vec0 virtual tables and the named indices):

- `meta(key TEXT PRIMARY KEY, value TEXT)`.
- `files(path TEXT PRIMARY KEY, mtime REAL, size INTEGER)` — per-file sync state, populated by the Phase 4 indexer and consumed by the Phase 6 `index sync` subcommand. Phase 1 only creates the table; it stays empty until Phase 4 runs.
- `chunks(id, path, language, project, start_line, end_line, kind, name, scope, content)`.
- `chunks_fts USING FTS5(content, name, scope, content='chunks', content_rowid='id')`.
- `embeddings USING vec0(chunk_id INTEGER PRIMARY KEY, embedding FLOAT[<dim>])`. **Dim handling:** Phase 1 does not embed anything; the virtual table needs a concrete dim. Use `768` (fastembed Jina v2 base code dim, the project default). Phase 2 may revise this when the backend is wired in; the dim mismatch path (`index.embed_dim_mismatch`) is registered in `Kinds` already, so a Phase 2 rebuild flow can rely on it.
- `symbols(id, chunk_id, name, kind, line)`.
- `edges(src_chunk_id, dst_name, kind, meta)`.
- Indices: `chunks(path)`, `chunks(language)`, `symbols(name)`, `edges(dst_name)`, `edges(src_chunk_id)`.

## Tests

`tests/test_storage.py`:

- `test_open_creates_fresh_db`: open against a `tmp_path` that does not exist; succeeds; file is created; `meta.schema_version == "1"`; `meta.code_index_version == code_index.__version__`.
- `test_wal_mode_enabled`: `PRAGMA journal_mode` returns `wal`.
- `test_fts_table_exists`: query `sqlite_master` for `chunks_fts` of type `table`.
- `test_vec_table_exists`: query `sqlite_master` for `embeddings`; if sqlite-vec is loaded the row exists.
- `test_files_table_exists`: query `sqlite_master` for a `files` table of type `table`; introspect `PRAGMA table_info('files')` and assert columns `path` (TEXT, PK), `mtime` (REAL), `size` (INTEGER) are present with the documented types. The table is empty after a fresh open.
- `test_all_indices_created`: query `sqlite_master` for the five indices named above.
- `test_reopen_does_not_remigrate`: open once, close, reopen; `meta.schema_version` is still `"1"` and migrations did not run again (assert via a sentinel: write a row to a table after first open, reopen, ensure the row still exists — proves no DROP happened).
- `test_schema_mismatch_raises`: manually write `meta.schema_version = "999"`, close, reopen with `check_version=True`; expect `CodeIndexError(code=10, kind="index.schema_mismatch")`.
- `test_discover_migrations_sorted`: `discover_migrations()` returns a list whose `from_version` fields are sorted numerically.
- `test_migration_runner_idempotent`: calling `run_migrations(conn, "1")` after the schema is already at `"1"` is a no-op (does not error, leaves data intact).
- (Conditional) `test_vec_extension_unavailable_raises`: if a build of sqlite-vec cannot be loaded in the test env (skip if it can), the open helper raises `CodeIndexError(code=10, kind="index.vec_extension_unavailable")`. The coder may instead test this by patching the loader to raise and asserting the translation; that is acceptable.
- (Conditional) `test_fts5_unavailable_raises`: hard to trigger because system SQLite usually has FTS5. Patch the availability probe to return False and assert `kind="index.fts5_unavailable"` is raised.

If the test module uses a shared introspection helper that enumerates expected tables (e.g. a constant like `EXPECTED_TABLES`), include `files` in that list alongside `meta`, `chunks`, `chunks_fts`, `embeddings`, `symbols`, `edges`.

## Definition of done

- `open_index` opens an existing index, creates a new one when missing, enables WAL, loads sqlite-vec, and verifies FTS5.
- The full schema sketch from `storage.md` is created by `0_to_1.py`: six tables (`meta`, `files`, `chunks`, `chunks_fts`, `embeddings`, `symbols`, `edges`) plus the named indices. The `files` table is created with columns `path TEXT PRIMARY KEY`, `mtime REAL`, `size INTEGER` and is empty after a fresh open.
- `meta.schema_version` is `"1"` after a fresh open.
- `meta.code_index_version` is set to `code_index.__version__` after a fresh open.
- Reopening a known-good index does not re-run migrations (idempotent).
- Schema-version mismatch raises with `code=10`, `kind="index.schema_mismatch"`.
- Vec extension unavailability raises with `code=10`, `kind="index.vec_extension_unavailable"` (test may patch the load probe).
- FTS5 unavailability raises with `code=10`, `kind="index.fts5_unavailable"` (test may patch the probe).
- `uv run pytest tests/test_storage.py` passes.
- `uv run pyright` passes.
- `uv run ruff check` passes.
