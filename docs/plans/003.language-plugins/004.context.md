## Parser

Tree-sitter via `tree-sitter-language-pack` (JS grammar — distinct from TS). Same module-level Parser singleton pattern as step 003.

`tree-sitter` and `tree-sitter-language-pack` are already declared in `pyproject.toml`'s base dependencies from the initial scaffold — no `pyproject.toml` edits needed in this step.

## Node mapping

| Tree-sitter node                                    | Action                                       |
|-----------------------------------------------------|----------------------------------------------|
| `function_declaration`                              | chunk kind `"function"`                      |
| `class_declaration`                                 | chunk kind `"class"`                         |
| `method_definition` (inside `class_body`)           | chunk kind `"function"`, scope = class name  |
| `lexical_declaration` whose initializer is `arrow_function` at module scope | chunk kind `"function"`, name = variable name |
| `export_statement` with `default` keyword           | symbol with synthetic name `"default::<stem>"` |
| `export_statement` with named export                | symbol(s) for exported names                 |
| `import_statement`                                  | edge per `imports()`                         |
| `call_expression` where callee is identifier `require` at module scope | edge per `imports()` |

Arrow functions not assigned at module scope (e.g. `[1,2].map(x => x+1)`) are NOT chunked. Only `const fn = () => {...}` / `let fn = () => {...}` / `var fn = () => {...}` at the top level.

## Default-export synthetic name

`path.stem` = filename without final extension. For `widget.js`, default export → `"default::widget"`. For `index.js`, `"default::index"`. This collision risk (every package's `index.js` produces the same symbol name) is by design — `chunking-and-languages.md` documents it and treats `scope` plus `--lang` as the disambiguators at query time.

## Imports — edge meta shape

`meta` is `dict | None`. For JS, always `dict` (not `None`) so consumers don't have to special-case shape. Fields used:

- `"names"`: `list[str]`. Imported binding names as written. For namespace imports, the string is literally `"* as ns"` (the star + alias form). Empty list for side-effect imports.
- `"form"`: `"esm"` (default, can be omitted) or `"require"` for CJS `require()` calls. Snapshot test pins which form the plugin emits.

Coder's call whether to always include `"form"` or only when it's `"require"`. The snapshot file is the contract.

## Error tolerance

Tree-sitter recovers; return what's parsed. Never raise.

## Fixture outline

`tests/fixtures/languages/javascript/sample.js`, roughly:

```javascript
import { useState } from "react";
import * as fs from "fs";
import "./side-effect";
const path = require("path");

export function namedExport() {
    return 1;
}

const arrowAtModuleScope = (x) => x + 1;

export class Widget {
    constructor() {}
    method() { return arrowAtModuleScope(1); }
}

export default function () {
    return new Widget();
}
```

## Out of scope

- JSX parsing (handled by TS plugin's TSX variant if at all).
- `ref` symbols.
- Re-export tracing (`export * from "mod"` is captured as an edge with `meta={"names": ["*"]}` if the coder chooses to support it; otherwise emit no symbol for it. Snapshot pins the choice).
