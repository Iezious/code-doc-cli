# Step 002 — context

## Authoritative source

[`../../architecture/chunking-and-languages.md`](../../architecture/chunking-and-languages.md), section "Python (`languages/python.py`)" and the symbol-identity convention `module.Class.method`.

## Parser

stdlib `ast`. Use `ast.parse(content, filename=str(path))` and walk the top-level body. Recurse into `ClassDef` bodies for methods (one extra level only — Python's idiomatic scope is class+method; deeper nesting is rare and still handled by the dotted-scope logic).

## Chunk kinds and how they map to AST nodes

| AST node          | Chunk `kind`     |
|-------------------|------------------|
| `FunctionDef`     | `"function"`     |
| `AsyncFunctionDef`| `"function"`     |
| `ClassDef`        | `"class"`        |
| top-level non-def | one `"module"` chunk spanning all such statements at module scope |

The module-body chunk is emitted iff at least one top-level statement is not a `FunctionDef` / `AsyncFunctionDef` / `ClassDef` / `Import` / `ImportFrom`. Imports are not part of the module-body chunk — they are tracked separately via `imports()`. (A file with only imports + defs has no module-body chunk.)

## Scope chaining

Build the dotted scope by walking the AST with a stack. The module's stem (`path.stem`) is NOT part of `scope` (that prefix is the indexer's job in Phase 4 if it needs cross-file dotted names). `scope` is purely intra-file:

- top-level `def foo` → `scope = None`.
- `class C: def m` → method's `scope = "C"`.
- `class C: def outer(): def inner()` → `inner`'s `scope = "C.outer"`.

## Symbol naming

`Symbol.name` is the dotted intra-file name (module stem NOT included for the same reason). `class C: def m` → `Symbol(name="C.m", kind="def", line=<def line>)`. The class itself → `Symbol(name="C", kind="def", line=<class line>)`.

## Imports

| Statement                         | Edge(s)                                       |
|-----------------------------------|-----------------------------------------------|
| `import x`                        | one `Edge(target="x", kind="import", ...)`    |
| `import x, y`                     | one edge per name (`"x"`, `"y"`)              |
| `import a.b`                      | `target="a.b"`                                |
| `import a.b as c`                 | `target="a.b"` (alias not recorded)           |
| `from a.b import c`               | `target="a.b.c"`                              |
| `from a.b import c, d`            | two edges, `"a.b.c"` and `"a.b.d"`            |
| `from . import sibling`           | `target=".sibling"` (relative; one leading dot per `level`) |
| `from ..pkg import x`             | `target="..pkg.x"`                            |

`Edge.line` is the statement's `lineno`. `Edge.meta` is `None` (Python imports have no extra structure worth recording here).

## Error tolerance

`ast.parse` raises `SyntaxError` on malformed input. Catch it and return `[]` from each method. Do not log — Phase 4 decides whether to emit a parsing warning at the indexer call site. (Phase 4 wraps plugin calls in try/except and applies skip-or-strict per `errors-and-exit-codes.md` code 30.)
