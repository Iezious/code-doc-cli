## Parser

Tree-sitter via `tree-sitter-language-pack`, **TS grammar** — distinct from the JS grammar. The pack ships separate `typescript` and `tsx` grammars; the plugin should accept both, dispatching by file extension at parse time (`.tsx` → `tsx` grammar, `.ts` → `typescript` grammar). Both extensions are advertised through `LANGUAGE.extensions` (`(".ts", ".tsx")`).

`tree-sitter` and `tree-sitter-language-pack` are already declared in `pyproject.toml`'s base dependencies from the initial scaffold — no `pyproject.toml` edits needed in this step.

## Node mapping — delta vs JS

In addition to everything in [`004.context.md`](004.context.md):

| Tree-sitter node                              | Chunk `kind`     |
|-----------------------------------------------|------------------|
| `interface_declaration`                       | `"interface"`    |
| `type_alias_declaration`                      | `"type"`         |
| `enum_declaration`                            | `"enum"`         |
| `internal_module` / `module` (namespace)      | `"namespace"`    |

`namespace`-nested declarations get the namespace's name added to their `scope` (same handling as C# namespaces).

## Type-only imports

The TS grammar marks type-only imports either via a `type` keyword child of `import_statement` (whole-statement type-only: `import type { X } from "..."`) or per-specifier (`import { type X, Y } from "..."`).

For Phase 3:

- Whole-statement type-only → one edge with `meta["type_only"] = True`.
- Per-specifier type-only is **not** disambiguated in Phase 3 — emit one edge for the whole statement with `meta["type_only"] = False` (or absent) and `meta["names"]` containing all names regardless of per-specifier `type` keywords. Document this in the snapshot. Phase 4+ may revisit if seam analysis needs the precision.

`meta["type_only"]` is `True` only when present and truthy; absence is treated as `False` by consumers. Coder picks whether to emit `"type_only": False` explicitly or omit the key.
