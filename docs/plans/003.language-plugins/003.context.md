## Parser

Tree-sitter via `tree-sitter-language-pack`. The pack bundles compiled grammars and exposes them through a small loader API. The plugin loads the C# language at module import time (acceptable cost — once per process) and reuses a single `Parser` across calls. Document the exact import path in the implementation (the pack's API has evolved; coder picks the stable surface at implementation time).

`tree-sitter` and `tree-sitter-language-pack` are already declared in `pyproject.toml`'s base dependencies from the initial scaffold — no `pyproject.toml` edits needed in this step.

## Chunk kinds — node mapping

The C# grammar's node types this plugin acts on:

| Tree-sitter node                       | Chunk `kind`     |
|----------------------------------------|------------------|
| `class_declaration`                    | `"class"`        |
| `struct_declaration`                   | `"struct"`       |
| `record_declaration`                   | `"record"`       |
| `interface_declaration`                | `"interface"`    |
| `enum_declaration`                     | `"enum"`         |
| `method_declaration`                   | `"function"`     |
| `local_function_statement`             | `"function"`     |
| `constructor_declaration`              | `"function"`     |
| top-level statements (file scope)      | one `"module"` chunk |

`property_declaration` and `field_declaration` are NOT chunked in Phase 3 — they are typically too small to be useful retrieval units and they live inside their enclosing type's chunk text. Phase 4 may revisit if BM25 quality suffers.

## Scope chaining

Walk down through `namespace_declaration` and any nesting `class_declaration` / `struct_declaration` / `record_declaration` / `interface_declaration`, accumulating dotted names. A method `Bar` inside `class Foo` inside `namespace A.B`: `scope = "A.B.Foo"`, `name = "Bar"`.

Generic type parameters: `class Box<T>` produces `name = "Box"` with `<T>` stripped. If recorded in `scope` for descendants, format as `"A.B.Box<T>"` — but a simpler approach (drop generics entirely from `scope` too) is also acceptable. Coder picks; the snapshot test pins the chosen behavior.

## Symbol naming

`Symbol.name = scope + "." + name` when `scope` is non-None, else `name`. Matches `chunking-and-languages.md`'s "Namespace.Type.Member" convention. `kind = "def"`. `line` is the node's `start_point.row + 1`.

No `ref` symbols in this phase.

## Imports

Each `using_directive` at the top of the file produces one `Edge`:

| Directive form                              | Edge target              | Edge meta              |
|---------------------------------------------|--------------------------|------------------------|
| `using System;`                             | `"System"`               | `None`                 |
| `using System.Collections.Generic;`         | `"System.Collections.Generic"` | `None`           |
| `using static System.Math;`                 | `"System.Math"`          | `None`                 |
| `using X = System.IO.Path;`                 | `"System.IO.Path"`       | `None`                 |
| `global using ...;`                         | same as `using`          | `None`                 |

`kind = "import"`. Alias names and `static` / `global` qualifiers are dropped from the edge surface — they don't matter for the symbol/graph layer.

## Error tolerance

Tree-sitter recovers from many errors. Don't try to detect "did it fail" — just walk what's there. If the root node has zero useful children, return `[]`. Never raise.

## Fixture outline

`tests/fixtures/languages/csharp/sample.cs` exercises one of each chunk kind plus the documented `using` forms. Keep the file small (~40–60 lines). One namespace, one class with one method and one constructor, one struct, one record, one interface, one enum, one top-level statement at file scope (if grammar supports it; safe to omit if the chosen grammar version chokes — document the choice in the test).
