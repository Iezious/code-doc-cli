# Step 002 context — rebuild CLI

## The `--yes` gate and the `usage.confirmation_required` kind

Phase 6 needs a `kind` for "destructive operation refused without confirmation". The existing kind registry (Phase 1 `errors.py`, `Kinds` class) does not have one. Two options:

1. **Add `Kinds.USAGE_CONFIRMATION_REQUIRED = "usage.confirmation_required"`** to the registry. This is the architecturally clean move (formal kind, listed in `errors-and-exit-codes.md`).
2. **Raise with a local string** `kind="usage.confirmation_required"`. Works because `CodeIndexError.kind` is just a string; the registry is documentation, not enforcement.

Phase 6 picks **option 2** for the implementation: pass the string literal directly. The kind is added to the registry only if the architect decides to formalize it in `outcome.md` (recorded in `outcome.md` as a candidate observation, **not** as a pre-commitment).

This keeps Phase 6 from making a contract change that belongs in `errors-and-exit-codes.md`, while keeping the `--format json` envelope coherent on day one.

## Exit code

`EXIT_USAGE` (= 1) per `errors-and-exit-codes.md`'s exit-code table ("usage error"). Already a constant in `code_index.errors`.

## Why no `--root` and no `--dry-run`

- **`--root`:** `index build` supports it as a Phase 4 override for "build against a subtree". `rebuild` is "I want what I had, fresh"; a different root would mean "build against a different tree", which is just `index build --root`. Keeping `rebuild` rootless avoids confusion.
- **`--dry-run`:** rebuild without dropping is a no-op (we already rebuilt nothing); rebuild with `--dry-run` is "tell me what you would build" which is exactly `index build --dry-run`. No new semantics.

Phase 6 does not introduce these flags; `cli.md` already documents `--yes` as the only flag on `rebuild`.

## What this step does NOT do

- Does not invent a new internal drop helper. Phase 4's `indexer.build` already owns the drop sequence (six DELETE statements + two `meta` key resets); this step just calls `indexer.build` and lets Phase 4 do the work.
- Does not run the pre-flight model/dim check. Per decision 7 in `context.md`, rebuild explicitly skips that check.
- Does not change `meta.schema_version`. Phase 4's drop path leaves it alone, and Phase 6 inherits that property.

## No step-specific test fixtures

Reuses the Phase 4 polyglot fixture under `tests/fixtures/projects/polyglot_minimal/`. No new fixture files.
