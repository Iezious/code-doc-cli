# src/code_index/sync.py
from dataclasses import dataclass
from pathlib import Path
import sqlite3

@dataclass
class SyncResult:
    files_added: int
    files_changed: int
    files_unchanged: int
    files_removed: int
    chunks_inserted_total: int
    seconds_elapsed: float

def delete_file_rows(conn: sqlite3.Connection, path: str) -> None:
    """Delete all rows for a single file from chunks, chunks_fts, embeddings,
    symbols, edges, and files. Order matters: dependent tables before chunks;
    finally files."""

def sync(
    config,
    root: Path,
    *,
    verbose: bool = False,
) -> SyncResult:
    """Incremental update against the existing index.

    Walks `root` using `walker.walk(root, config)`, joins each walked file
    against the `files` table by path, and dispatches to per-file insert /
    re-insert / no-op / delete based on the mtime+size comparison documented
    in context.md ("Sync algorithm spec").

    Assumes the standard Phase 6 pre-flight check (index exists, embed model
    and dim match) has already run in the CLI layer.
    """
```

# src/code_index/cli.py — replaces the existing stub
@index_app.command("sync")

    ctx: typer.Context,
    verbose: bool = typer.Option(False, "--verbose"),
) -> None: ...
```

CLI wrapper behavior:

1. Run the pre-flight check (see `context.md` "Cross-cutting constraints"): discover config, verify index exists, read `meta.embed_model` and `meta.embed_dim`, compare against `embeddings.from_config(config)`.
2. Call `sync.sync(config, root, verbose=verbose or ctx.obj["verbose"])`.
3. Emit summary on stdout:
   - `--format text`: one human line, e.g. `synced: +A ~C =U -R (N chunks) in S.SSs`.
   - `--format json`: the JSON shape pinned in `context.md` ("JSON output shapes" → `index sync`).
4. Exit 0 on success. `CodeIndexError` is caught by the existing boundary handler.

## Tests

`tests/test_sync_engine.py` exercises `sync.sync(...)` directly with mocked plugins and a mocked `EmbeddingBackend` (same pattern as Phase 4's `test_indexer_pipeline.py`):

- **No-op sync.** Build a tree, run `indexer.build`, run `sync.sync` immediately. Result: `files_unchanged == N`, every other count 0. No row IDs in `chunks` change.
- **New file.** After initial build, add a new file under the root. Run `sync.sync`. Result: `files_added == 1`. The new file has rows in all five row-data tables and a `files` row with correct mtime/size.
- **Changed file (mtime).** Touch one file (rewrite content, advance mtime). Result: `files_changed == 1`. The old `chunks.id` values for that file are gone; new ones exist; other files' `chunks.id` values are unchanged.
- **Changed file (size only).** Same as above but mtime is manually reset to its original value while size differs. Result: `files_changed == 1`.
- **Removed file.** After initial build, delete one file from disk. Run `sync.sync`. Result: `files_removed == 1`. No rows for that path exist in any of the five row-data tables, and no `files` row.
- **Mixed.** One added, one changed, one removed, two unchanged in the same call.
- **`delete_file_rows` happy path.** Direct unit test against a populated DB: insert sentinel rows for path `"x"` and path `"y"`, call `delete_file_rows(conn, "x")`, assert all rows for `"x"` are gone from `chunks`, `chunks_fts`, `embeddings`, `symbols`, `edges`, `files`, and rows for `"y"` are untouched.

`tests/test_sync_cli.py` exercises the CLI wrapper:

- **Missing index.** Run `code_index index sync` in a `tmp_path` with `docs/.helpers/config.toml` but no `index.sqlite`. Exit code 12; under `--format json`, envelope `kind == "index.missing"`.
- **Embed model mismatch.** Build a fixture, then manually `set_meta(conn, "embed_model", "other:model")`. Run sync. Exit code 11; envelope `kind == "index.embed_model_mismatch"`; message references `code_index index rebuild`.
- **Embed dim mismatch.** Same approach, set `embed_dim` to `"512"`. Exit code 11; `kind == "index.embed_dim_mismatch"`.
- **JSON summary shape.** Run sync against a built fixture with `--format json`; assert `json.loads(stdout)` matches the shape pinned in `context.md`.

## Definition of done

- `sync.sync(...)` returns a `SyncResult` whose counts match the disk delta for every scenario tested above.
- `delete_file_rows(conn, path)` deletes from all six row tables (`chunks`, `chunks_fts`, `embeddings`, `symbols`, `edges`, `files`) and from no others.
- The CLI wrapper runs the standard pre-flight check; mismatches raise the documented `CodeIndexError`.
- Stdout under `--format json` matches the `index sync` shape in `context.md`.
- `uv run pytest tests/test_sync_engine.py tests/test_sync_cli.py` passes.
- `uv run ruff check src/code_index/sync.py src/code_index/cli.py tests/test_sync_engine.py tests/test_sync_cli.py` passes.
- `uv run pyright src/code_index/sync.py` passes.
