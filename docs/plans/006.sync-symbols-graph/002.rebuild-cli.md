# Step 002 — `index rebuild` CLI

## Goal

Replace the `code_index index rebuild` stub with a thin wrapper around `indexer.build(config, root)`. Gate the destructive drop+rebuild behind the user-facing `--yes` confirmation flag.

## Files to create or modify

- `src/code_index/cli.py` (edit — replace the `index rebuild` stub)
- `tests/test_rebuild_cli.py` (new)

## Signatures

```python
# src/code_index/cli.py — replaces the existing stub
@index_app.command("rebuild")
def cli_index_rebuild(
    ctx: typer.Context,
    yes: bool = typer.Option(False, "--yes", help="confirm destructive rebuild"),
    verbose: bool = typer.Option(False, "--verbose"),
) -> None: ...
```

CLI wrapper behavior:

1. **No pre-flight model/dim check.** Per decision 7 in `context.md`, `index rebuild` is about to drop the data; it must not refuse on model mismatch (rebuild is the cure for model mismatch).
2. Discover the config; resolve the project root (parent of `docs/.helpers/`).
3. If `--yes` is not set, raise `CodeIndexError(EXIT_USAGE, Kinds.CLI_NOT_IMPLEMENTED, "...")` — **no**, use `EXIT_USAGE` directly with a fresh message; do **not** invent a new `Kinds.*` value. The error envelope `kind` should be a plain `"usage.confirmation_required"` string that lives only on this raise site, **or** the coder may pass `kind="cli.not_implemented"` — neither is right. Resolution: use `kind=Kinds.CLI_NOT_IMPLEMENTED`? No. See `002.context.md` for the resolved approach (use raw `kind="usage.confirmation_required"` as a local-only string; document in `outcome.md` only if the architect wants to formalize it).
4. Call `indexer.build(config, project_root, dry_run=False, verbose=verbose or ctx.obj["verbose"])`. The auto-rebuild drop path inside `indexer.build` (Phase 4) does the destructive work.
5. Emit summary on stdout, reusing `index build`'s JSON shape (Phase 4):
   - `--format text`: same one-line summary as `index build`, e.g. `indexed 7 files, 23 chunks in 4.2s`.
   - `--format json`: same shape as `index build` (`files_walked`, `files_chunked`, `chunks_inserted`, `symbols_inserted`, `edges_inserted`, `seconds_elapsed`).
6. Exit 0 on success; `CodeIndexError` is caught by the existing boundary handler.

`--root` flag is **not** supported on `rebuild` (Phase 4 supports it on `index build` for override; `rebuild` is "redo what we just had", so it always uses the config-resolved root). This keeps the surface narrow.

`--dry-run` is **not** supported either — already redundant with `index build --dry-run`.

## Tests

`tests/test_rebuild_cli.py` uses `CliRunner` with `monkeypatch.chdir` against a copy of `tests/fixtures/projects/polyglot_minimal/` (the Phase 4 fixture). Cases:

- **Happy path.** Run `code_index init` and `code_index index build`. Snapshot row counts in `chunks`, `chunks_fts`, `embeddings`, `symbols`, `edges`, `files`. Run `code_index index rebuild --yes`. Exit 0. Row counts in all six tables match the original build's counts (rebuild is idempotent against the same tree).
- **Missing `--yes`.** Run `code_index index rebuild` (no flag) against a built fixture. Exit code `1`; stderr message mentions `--yes`; under `--format json`, envelope `code == 1` and `kind == "usage.confirmation_required"`.
- **JSON summary shape.** Run `code_index index rebuild --yes --format json` against a built fixture. `json.loads(stdout)` matches the `index build` shape (`files_walked`, `files_chunked`, `chunks_inserted`, `symbols_inserted`, `edges_inserted`, `seconds_elapsed`).
- **No pre-flight model check.** Build a fixture, manually set `meta.embed_model = "wrong:model"`, run `code_index index rebuild --yes`. Exit 0 (rebuild does not refuse on model mismatch); after the run, `meta.embed_model` reflects the configured backend's name (the auto-rebuild drop+repopulate in `indexer.build` overwrites it).
- **No index yet.** Run `code_index index rebuild --yes` in a `tmp_path` with `docs/.helpers/config.toml` but no `index.sqlite`. Exit 0 — `indexer.build` creates the index file on first run, same as `code_index index build` would. (This is a degenerate but well-defined case: rebuild from nothing equals build from nothing.)

## Definition of done

- `code_index index rebuild --yes` against a populated fixture drops and repopulates all six row-data tables, with row counts matching what `index build` produced.
- `code_index index rebuild` without `--yes` exits `1` with `kind="usage.confirmation_required"` under `--format json`.
- The pre-flight model/dim check is **not** run on rebuild (rebuild from a model-mismatched index succeeds).
- `--format json` output matches the `index build` shape.
- `uv run pytest tests/test_rebuild_cli.py` passes.
- `uv run ruff check src/code_index/cli.py tests/test_rebuild_cli.py` passes.
- `uv run pyright src/code_index/cli.py` passes.
