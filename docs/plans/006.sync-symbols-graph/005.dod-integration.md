# Step 005 — end-to-end Phase 6 DoD integration test

## Goal

Prove the full Phase 6 DoD against the polyglot fixture: edit one file, sync, verify only that file changed; symbols / graph queries return expected hits; rebuild produces a fully populated index.

## Files to create or modify

- `tests/test_phase6_dod.py` (new)

No new fixture files. Reuses `tests/fixtures/projects/polyglot_minimal/` from Phase 4.

## Test outline

Single integration test (split into smaller `def test_*` if the coder prefers; the steps below are the asserts that must run, not necessarily a single function).

1. **Setup.** Copy `tests/fixtures/projects/polyglot_minimal/` to `tmp_path` via `shutil.copytree`. `monkeypatch.chdir(tmp_path)`.
2. **Build.** Run `code_index init` then `code_index index build` via `CliRunner`. Open the resulting `docs/.helpers/index.sqlite` via `open_index`.
3. **Snapshot pre-sync state.** Record the full `chunks` table as a list of tuples `(id, path)` — this is the identity reference. Record `(path, mtime, size)` for every row in `files`. Record total row counts in `chunks`, `chunks_fts`, `embeddings`, `symbols`, `edges`, `files`.
4. **Mutate one file.** Append a new function definition to `main.py`:
   ```python
   def newly_added_symbol():
       return "phase6_marker"
   ```
   Ensure the file's mtime is advanced (write + `os.utime` if necessary; on fast filesystems a second write within the same mtime tick can be invisible — touch with a forced mtime).
5. **Sync.** Run `code_index index sync`. Exit 0. Capture stdout (or `--format json` for structured assertions).
6. **Assert one file changed.** Re-read the `chunks` table. Assertions:
   - Every `(id, path)` row from the snapshot where `path != "main.py"` still exists with the same `id` (other files were not touched).
   - All rows for `path == "main.py"` from the snapshot are gone (replaced with new `id`s).
   - At least one new row exists for `path == "main.py"` whose `name == "newly_added_symbol"` (or whichever name the polyglot fixture's python plugin emits for the added function — the test reads it from the new rows rather than hardcoding the convention).
   - `files` row for `main.py` has updated `mtime` and `size` matching the new file on disk.
   - Every other `files` row matches the snapshot exactly.
   - Row counts in `chunks_fts`, `embeddings`, `symbols`, `edges` are consistent with the new state (no orphans: `chunks_fts.rowid` covers exactly the live `chunks.id` set).
7. **`symbols defs`.** Run `code_index symbols defs newly_added_symbol --format json`. Parse stdout. Assert at least one hit; the hit's `path == "main.py"`, `language == "python"`, `name == "newly_added_symbol"`, `scope` matches the fixture's python plugin's convention (likely `"main"`).
8. **`symbols refs`.** Run `code_index symbols refs <known_ref_name> --format json` for a name the polyglot fixture's plugins emit as `ref`. The polyglot fixture is owned by Phase 4; this test reads the fixture's actual emitted symbols rather than hardcoding language conventions. If no `ref` rows exist in the polyglot fixture at all, the test asserts `symbols refs` returns `[]` and continues — empty is still a valid outcome (no `kind=ref` in the polyglot).
9. **`graph callers`.** Pick a symbol name that appears in `edges.dst_name` (read from the DB to find one). Run `code_index graph callers <name> --format json`. Assert at least one hit with the expected source chunk's `path`.
10. **`graph deps`.** Run `code_index graph deps main.py --format json`. Assert at least one hit. Assert the result includes both resolved and unresolved `dst_name` values if any unresolved targets exist in the fixture (e.g. external imports like `os` for Python — there is no `symbols` row for `os`, so it is unresolved by construction). If the fixture happens to have no unresolved targets, the test does not synthesize one; it just records the observation. The contract is "graph deps returns unresolved when they exist", not "the test must exercise unresolved targets".
11. **Rebuild.** Run `code_index index rebuild --yes`. Exit 0. Re-open the DB and assert all six row-data tables (`chunks`, `chunks_fts`, `embeddings`, `symbols`, `edges`, `files`) have row counts matching the post-sync state (rebuild is idempotent against the unmodified post-sync tree). `meta.embed_model` and `meta.embed_dim` are present.

## Definition of done

- The test runs end-to-end via `uv run pytest tests/test_phase6_dod.py` and passes.
- Every assertion above is realized in code (steps 6, 7, 9, 10, 11 are the load-bearing ones; the others are setup/snapshot).
- The test does **not** import `code_index.sync`, `code_index.symbols`, or `code_index.graph` directly — it drives the binary through `CliRunner`. The internal modules are exercised through the CLI surface.
- Reuses the Phase 4 polyglot fixture without modification.
- The first run downloads the fastembed model (~120 MB) per Phase 2's contract; subsequent runs use the cache at `tests/.cache/fastembed/`.
- `uv run pytest` (full suite) passes — this step's test plus everything below it.
- `uv run ruff check tests/test_phase6_dod.py` passes.
- `uv run pyright` passes for the full repo.
