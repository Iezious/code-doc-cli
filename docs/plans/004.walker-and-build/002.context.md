# Step 002 context — init

## Template for `docs/.helpers/config.toml`

Per the "What `init` writes" section of
[`../../architecture/config.md`](../../architecture/config.md), the skeleton
is intentionally minimal:

```toml
[code_index]
version       = ">=<X.Y>,<<X.(Y+2)>"
project       = "<directory-name>"
roots         = ["."]
embed_backend = "fastembed"
embed_model   = "jinaai/jina-embeddings-v2-base-code"
```

- `version`: the engine's running version dictates the pin. For engine
  `0.3.x`, write `">=0.3,<0.5"`. For engine `0.4.x`, write `">=0.4,<0.6"`.
  In general: `">={major}.{minor},<{major}.{minor+2}"`. Read the running
  engine version from `importlib.metadata.version("code_index")` (Phase 1
  already exposes this; if not, fall back to a constant in
  `src/code_index/__init__.py`).
- `project`: from the `--name` flag if given, otherwise the basename of
  the project root (the directory containing `docs/.helpers/`, which is
  CWD at `init` time).
- `roots`, `embed_backend`, `embed_model`: literal values above.

Do not write `embed_batch_size` (lets the default carry), `languages`
(lets all seven be active), `ignores` (empty default), or
`extra_languages` (empty default). Keep the file small per the rationale
in config.md.

## Template for `docs/.helpers/.gitignore`

Three lines plus trailing newline:

```
index.sqlite
index.sqlite-wal
index.sqlite-shm
```

## Idempotency rules

- If `docs/.helpers/config.toml` exists and `--force` is not set: refuse.
  Exit with the Phase 1 error envelope. The most appropriate `kind` is
  arguably `usage` (code `1`) since the user attempted to clobber an
  existing artifact; the coder should pick the closest matching `kind`
  from the Phase 1 errors module and document the choice in the
  step-level test. Stdout stays empty (per cli.md). Stderr carries the
  one-line message.
- If `--force` is set: overwrite `config.toml` unconditionally.
- `.gitignore`: write only if it does not exist or its content differs
  from the template. Re-writing an identical file is a no-op (don't
  touch mtime unnecessarily; just skip the write).
- The `docs/.helpers/` directory is created with `Path.mkdir(parents=True,
  exist_ok=True)`.

## Output discipline

- On success: a single human-readable line on stdout summarizing what
  was written, e.g. `wrote docs/.helpers/config.toml`. Under
  `--format json` (if Phase 1 wired it through): a JSON object with the
  written paths. The Phase 7 JSON polish will tighten the JSON shape; in
  Phase 4 it is enough that something stable comes out.
- On refuse-without-force: empty stdout, one-line stderr, non-zero exit.

## Test runner notes

- `CliRunner` does not change CWD. Use `monkeypatch.chdir(tmp_path)`
  before `runner.invoke(...)` so the CLI's "project root = CWD"
  discovery resolves under `tmp_path`.
- For the `--name` test, read the file back and parse it with `tomllib`
  to assert `data["code_index"]["project"] == "custom-name"`. Do not
  regex the TOML text.

## Out-of-scope clarifications

- No interactive prompts. `init` is fully non-interactive.
- No git initialization. The user runs `git init` themselves.
- No "init populates the index" step. The user runs `index build`
  afterward. Step 004 covers that.
