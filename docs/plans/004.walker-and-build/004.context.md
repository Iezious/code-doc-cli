# Step 004 context — `index build` CLI

## Fixture file contents

Each source file is tiny but must be real enough that the corresponding
Phase 3 plugin produces at least one `Chunk` and at least one `Symbol` /
`Edge`. Suggested minimal shapes (the coder may adjust to whatever the
Phase 3 plugins actually emit per their snapshot tests):

- **`main.py`** — one `import` line and one `def`:
  ```python
  import os

  def greet(name):
      return f"hello {name}"
  ```
- **`main.cs`** — one `using` and one class with one method.
- **`main.js`** — one `import` and one exported function.
- **`main.ts`** — one `import type` and one exported function with a type
  annotation.
- **`main.go`** — `package main`, one `import`, one function.
- **`main.fs`** — one `namespace` / `module` and one `let` definition.
  Per chunking-and-languages.md, F# without a `.fsproj` warns but
  continues. We do not check in a `.fsproj` for this fixture; the warning
  is expected and acceptable.
- **`main.lsl`** — one `default` state with one event handler that calls
  `llSay`.

- **`.gitignore`** at root:
  ```
  ignored/
  ```

- **`ignored/skip_me.py`** — any content; this file must not appear in
  the index because the root `.gitignore` excludes the directory. Note
  that the fixture does NOT include a `.git/` directory — the walker only
  honors `.gitignore` when `.git/` is present. To make the test
  deterministic, create an empty `.git/` directory inside `tmp_path`
  *during* the test (before invoking `index build`), so that the
  `.gitignore` becomes active. Do not check in `.git/`; create it via
  `(tmp_path / ".git").mkdir()`.

- **`data.bin`** — 16 bytes starting with `b"\x00binary"`. The NUL byte
  triggers the binary probe. The file has no plugin-registered extension
  (`.bin` is not in any plugin), so the extension filter alone would
  exclude it; the NUL probe is the belt-and-suspenders second guard.

## CWD-injection mechanism for tests

`CliRunner` does not change CWD. Use `monkeypatch.chdir(tmp_path)` before
invoking the runner. This causes the Phase 1 config-discovery walk to find
`docs/.helpers/config.toml` under `tmp_path`.

There is no `CODE_INDEX_PWD` env var contract — that was a briefing
shorthand. The actual mechanism is `monkeypatch.chdir`.

## JSON output shape

Under `--format json`, the success body on stdout is exactly one JSON
object:

```json
{
  "files_walked": 7,
  "files_chunked": 7,
  "chunks_inserted": 12,
  "symbols_inserted": 18,
  "edges_inserted": 9,
  "seconds_elapsed": 4.21
}
```

Field names match `IndexerResult` exactly. Phase 7's JSON polish may add
fields or wrap this in a top-level envelope; the field names above will
not change.

## Failure paths

- No `docs/.helpers/config.toml` discovered: the Phase 1 config-discovery
  helper raises the standard `index.missing` / config error; let it
  propagate to the Phase 1 CLI exception handler. Do not catch.
- `indexer.build(...)` raises `CodeIndexError` (e.g. backend init
  failed): same — let it propagate.
- Walker / per-file errors are already handled inside `build(...)`; the
  CLI sees a normal `IndexerResult` and exits 0.

## Auto-rebuild and the second invocation

The second `index build` against the same fixture is the auto-rebuild
case from step 003's tests, re-exercised here at the CLI level. The
assertion is "row counts are equal" — not "row counts are double",
which is what would happen if drop logic were missing.

## Scope reminders

- Only `--root`, `--dry-run`, `--verbose` flags on `index build`. No
  `--strict`, no `--force`, no `--config` *override* at this layer
  (the `--config` global flag from Phase 1 still works).
- The fixture does not exercise `extra_languages`; that is Phase 3 test
  surface.
- Single `--root` value, not a list. Multi-root support stays at the
  config level only.
