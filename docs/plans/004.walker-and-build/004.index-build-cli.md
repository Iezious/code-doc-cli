# Step 004 — `index build` CLI and end-to-end DoD

## Goal

Replace the Phase 1 `code_index index build` stub with a thin wrapper around
`indexer.build(...)` (step 003), and prove the whole phase end-to-end against
a polyglot fixture project. This step owns the phase DoD.

## Files

- `src/code_index/cli.py` (edit — replace the `index build` stub)
- `tests/test_index_build_cli.py` (new)
- `tests/fixtures/projects/polyglot_minimal/` (new — fixture tree)
  - `.gitignore` (root) — lists `ignored/`
  - One source file per language: `main.py`, `main.cs`, `main.js`,
    `main.ts`, `main.go`, `main.fs`, `main.lsl`. Tiny but real content
    (one or two definitions each, parseable by the Phase 3 plugin).
  - `ignored/skip_me.py` — must NOT appear in the index.
  - `data.bin` — first 8 KiB contain a NUL byte. Must NOT appear.

## Signatures

```python
# src/code_index/cli.py
# 'index' is a Typer sub-app wired in Phase 1's scaffold.
@index_app.command(name="build")
def index_build(
    root: Path | None = None,
    dry_run: bool = False,
    verbose: bool = False,
) -> None: ...
```

The function:

1. Discovers the config (walk up from CWD for `docs/.helpers/config.toml`;
   helper already exists from Phase 1).
2. Determines the walk root: `root` flag if given (single value in Phase
   4); otherwise the project root (parent of `docs/.helpers/`).
3. Calls `indexer.build(config, root, dry_run=dry_run, verbose=verbose)`.
4. Prints a summary on stdout: one human line under `--format text`
   (e.g. `indexed 7 files, 23 chunks`), or a JSON object under
   `--format json` with `files_walked`, `files_chunked`,
   `chunks_inserted`, `symbols_inserted`, `edges_inserted`,
   `seconds_elapsed`.
5. Exits 0 on success. On `CodeIndexError`, exits via the standard
   Phase 1 envelope handler.

## Tests

`tests/test_index_build_cli.py`:

- **DoD integration test.** Copy
  `tests/fixtures/projects/polyglot_minimal/` to `tmp_path` via
  `shutil.copytree`. Run `code_index init` then
  `code_index index build --root <tmp_path>` via `CliRunner` (with
  `monkeypatch.chdir(tmp_path)`). Open the resulting
  `docs/.helpers/index.sqlite` and assert:
  - At least one row in `chunks` per language (filter by `language`
    column for each of the seven plugin names).
  - Zero `chunks` rows whose `path` starts with `ignored/`.
  - Zero `chunks` rows whose `path` ends in `data.bin`.
  - `meta` table has `embed_model` matching the configured fastembed
    default, and `embed_dim == "768"`.
  - `chunks_fts` row count equals `chunks` row count.
  - `symbols` and `edges` tables each have `> 0` rows (exact counts
    not asserted to avoid coupling to Phase 3 plugin internals).
  - `files` row count equals the number of source files actually
    indexed: the seven `main.*` files at root (one per language).
    `ignored/skip_me.py` and `data.bin` are absent from `files`. Every
    `files.path` value matches a value in `SELECT DISTINCT path FROM
    chunks` (forward-slash relative path, byte-for-byte equal).
- **Auto-rebuild.** Run `index build` a second time against the same
  tree; the run exits 0 and the row counts are equal to (not double of)
  the first run. This applies to `files` as well — still seven rows,
  not fourteen.
- **`--dry-run`.** Fresh fixture; `index build --root <tmp_path>
  --dry-run` exits 0. `docs/.helpers/index.sqlite` either does not
  exist or has zero rows in `chunks` and zero rows in `files`. Either
  is acceptable (coder decides whether dry-run still opens the DB).
- **No config found.** Run `index build` from a `tmp_path` with no
  `docs/.helpers/`. Exits non-zero with an error envelope pointing at
  `code_index init` (the Phase 1 config-discovery error path; this
  test just confirms the wrapper does not bypass it).

The fastembed model cache is reused from Phase 2's
`tests/.cache/fastembed/`. If CI runs cold, this test will download
~120 MB on first run — that is acceptable and matches the Phase 2
contract.

## Definition of done

- All four `tests/test_index_build_cli.py` cases pass, including the
  integration test (which is the phase DoD).
- The polyglot fixture is checked in under
  `tests/fixtures/projects/polyglot_minimal/`, complete with the
  `ignored/` directory and `data.bin`.
- `code_index init && code_index index build` against the fixture
  populates all six indexer-owned tables (`chunks`, `chunks_fts`,
  `embeddings`, `symbols`, `edges`, `files`) with the expected rows;
  `ignored/` and `data.bin` are absent from every one of them.
- The `files` table has exactly one row per successfully chunked
  source file (seven rows for the polyglot fixture), and each
  `files.path` matches the corresponding `chunks.path`.
- A second `code_index index build` against the same project
  succeeds and row counts match (auto-rebuild).
- `uv run pytest` passes for the whole suite (this step's tests plus
  steps 001 - 003 already passing).
- `uv run ruff check` passes.
- `uv run pyright` passes.
