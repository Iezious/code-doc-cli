# Step 001 context — walker

## Rule precedence

When a file would be excluded by more than one source, exclusion wins; there
is no override. The order the walker checks is incidental, but for
debuggability the recommended order is:

1. Built-in default excludes (cheap path-prefix or basename match).
2. `.gitignore` (only if `<root>/.git/` exists). Use `pathspec` with
   `GitWildMatchPattern`.
3. `config.ignores` (use `pathspec` with the same `GitWildMatchPattern` so
   syntax is consistent with what users see in `.gitignore`).
4. Extension filter: file extension must be in the set returned by the
   plugin registry for the active languages.
5. Max-file-size cap.
6. Binary-byte probe (first 8 KiB scanned for NUL). The architecture says
   this is the second guard for "unknown-extension" files; since step 4
   already filters by extension, in practice the probe acts as a belt-and-
   suspenders check for files whose extension matches a plugin but whose
   content is binary (e.g. a `.py` file accidentally containing a packed
   blob). Apply the probe to all files that pass step 4; do not restrict it
   to "unknown extension only" — that wording in architecture.md predates
   the explicit extension filter at the walker level and is captured as an
   observation for the architect in `outcome.md`.

## Registry call for active extensions

Phase 3's `LanguageRegistry` (returned by `active_plugins(config)`) exposes
the active plugin instances. Each instance has an `extensions: tuple[str, ...]`
attribute per the `Language` Protocol in
[`../../architecture/chunking-and-languages.md`](../../architecture/chunking-and-languages.md).
The walker derives its accepted-extension set by flattening
`{ext for p in active_plugins(config) for ext in p.extensions}`. If Phase 3
ships a dedicated `extensions()` method on the registry, use that instead;
either form is acceptable as long as the walker does not hard-code the
extension list.

## `pathspec` usage notes

- Pattern objects are constructed from the raw text of the `.gitignore`
  file via `pathspec.PathSpec.from_lines("gitwildmatch", lines)`.
- Match against the path **relative to the directory containing the
  `.gitignore`**, not relative to the walk root. Nested `.gitignore` files
  apply to their own subtree; combine using composition (check each
  `PathSpec` along the path from root to the file).
- For directory matches (`foo/`), pass `path + "/"` to `match_file` so the
  trailing-slash semantics work.

## Binary probe details

- Read at most the first 8 KiB (`f.read(8192)`) in binary mode. Check for
  `\x00` in the bytes. Do not attempt to decode here; this probe is
  pre-decode.
- If the probe says binary, do not open the file again for decoding.

## Encoding fallback

- Decode bytes (the full file contents) as UTF-8 strict on the first
  attempt. On `UnicodeDecodeError`, decode again with
  `errors="replace"`, emit a stderr warning naming the path, and set
  `decode_warning=True` on the `WalkedFile`.

## Stderr warning helper

Use the Phase 1 errors module helper (named `write_log_stderr` in the
briefing; the coder should use whatever the actual name turned out to be in
`src/code_index/errors.py` from Phase 1). The walker never raises on a
per-file problem in Phase 4 — skip + warn only.

## Symlinks

- `Path.is_symlink()` is the gate. For symlinks: if the link target is a
  file, follow and yield; if a directory, skip silently (it is not an error
  — it is the documented policy). If the link target does not exist
  (`Path.exists()` is `False` after resolving), warn and skip.
- Inode-based loop detection is explicitly out of scope per
  architecture.md; the directory-symlink-skip rule prevents loops.

## Test fixture layout

Suggested subdirectory layout under `tests/fixtures/walker/`:

- `gitignore_basic/` — has a `.git/` directory marker, a `.gitignore`, and
  files inside and outside the ignored path.
- `gitignore_nested/` — nested `.gitignore` overrides root rules.
- `gitignore_no_git/` — same as `gitignore_basic` but no `.git/`; the
  ignored path is yielded because `.gitignore` is silently inactive.
- `default_excludes/` — files under `node_modules/`, `.venv/`,
  `docs/.helpers/` must not be yielded.
- `extensions/` — files with `.py`, `.txt`, `.foo`; only the
  plugin-registered extensions are yielded.
- `symlinks/` — file symlink, directory symlink, broken symlink.
  Symlinks are created at test time (Windows requires admin or developer
  mode for symlink creation; mark the symlink tests with
  `pytest.mark.skipif(not _can_symlink, reason="...")` or use
  `os.symlink` with a per-test capability probe).
- `encoding/` — a file with non-UTF-8 bytes (`latin-1` content) checked
  in as a binary fixture.
- `oversize/` — generated at test time to avoid checking in a 1 MiB
  blob.

## Out-of-scope clarifications

- The walker does not call any plugin's `chunk` / `symbols` / `imports`
  methods. It only reads `plugin.extensions`.
- The walker does not touch storage or embeddings.
- `--strict` is not implemented. The walker has no `strict` parameter.
