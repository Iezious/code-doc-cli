## Polyglot fixture: conceptual-query augmentation

Phase 4's polyglot fixture
(`tests/fixtures/projects/polyglot_minimal/`) contains one source
file per language with "tiny but real content". To exercise the
"known conceptual query" DoD bullet, one fixture source needs a
clear natural-language phrase that the dense model can lock onto.

Option A (preferred): add a docstring or comment to an existing
fixture source. Example: in `main.py`, add
```python
def search_me() -> None:
    """Handle dropped websocket sessions with a reconnection loop."""
    pass
```
This adds one symbol-name query target (`search_me`) and one
conceptual-query target ("websocket reconnection on drop") in one
function chunk. Document the choice in the test file's docstring.

Option B: add a small extra fixture file. Discouraged — Phase 4
already pinned the fixture shape; this step should reuse it.

Either way, the fixture edit lives **with this step's tests**
(under `tests/fixtures/projects/polyglot_minimal/`); the change is
small and additive, not a Phase 4 rework.

## `cli.bad_enum` vs `config.bad_enum`

Phase 1 introduced `Kinds.CONFIG_BAD_ENUM` for unknown values of
`embed_backend`. The `--mode` flag is a CLI-layer enum, not a
config-file enum. The clean choice:

- **Reuse `Kinds.CONFIG_BAD_ENUM`** (code 2) with a clarifying
  message that names `--mode`. Lower friction; no new kind to
  document.
- **Add `Kinds.CLI_BAD_ENUM`** (code 1) and register it in
  `errors-and-exit-codes.md`. Cleaner separation of CLI usage
  errors vs config errors.

Recommendation: **reuse `Kinds.CONFIG_BAD_ENUM`** for MVP. Adding a
new kind requires an architect-side update to
`errors-and-exit-codes.md`; the cost is not justified for one
enum check that Typer's own enum validator could also catch. The
coder may instead use `typer.Option(..., case_sensitive=False)` with
a `Literal["bm25", "dense", "hybrid"]` type or an `enum.Enum`
subclass — both produce a Typer-level usage error (exit code 2) on
bad input, which already satisfies the contract. Document the
final choice inline.

## Session-fixture model-cache reuse

The DoD tests run real `index build` against the polyglot fixture,
which embeds 7 source files via fastembed. This requires the
fastembed model — already downloaded by Phase 2 tests into
`tests/.cache/fastembed/`. The session-scoped fixture in this
step:

- Sets `FASTEMBED_CACHE_DIR` (or whatever env var Phase 2 chose)
  to the same `tests/.cache/fastembed/` directory before invoking
  `init` and `index build`.
- Reuses the same fixture across every test in this file
  (`scope="session"`) so the build cost is paid once per pytest
  invocation.
- Function-scoped tests that need to mutate the index (e.g. the
  model-drift test) copy the index file to a function-scoped
  `tmp_path` first, then point `CliRunner` at that copy via
  `--config` or by chdir into the copy.

If Phase 2's cache env-var convention differs, follow that.

## CWD injection for `CliRunner`

`code_index init` and `code_index index build` operate on CWD; the
test must `monkeypatch.chdir(project_dir)` before each `CliRunner`
invocation. `CliRunner` itself does not chdir. The Phase 4
integration tests already use this pattern; mirror it.

## JSON result shape (the contract pinned here)

```json
{
  "results": [
    {
      "path": "src/foo/bar.py",
      "start_line": 12,
      "end_line": 28,
      "language": "python",
      "kind": "function",
      "name": "search_me",
      "scope": "bar",
      "excerpt": "def search_me() -> None:\n    ...",
      "score": 0.032786885245901641
    }
  ]
}
```

Zero results: `{"results": []}`. Errors: the standard Phase 1
envelope `{"error": {...}}` on stdout, per
`errors-and-exit-codes.md`.

This shape is the per-subcommand JSON contract for `search`. It is
**not** yet documented in `cli.md` — recorded in
[`outcome.md`](outcome.md) for the architect to fold in. Phase 7's
"JSON polish" pass standardizes shapes across all subcommands; this
step pins the `search` shape now so Phase 7 can adopt it as-is.
