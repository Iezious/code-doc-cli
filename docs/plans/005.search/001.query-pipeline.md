# Step 001 — Query pipeline

## Goal

Implement `src/code_index/search.py`: the hybrid BM25 + dense retrieval
pipeline with RRF fusion, filter-on-both-pools, mode selection, and the
`SearchResult` row shape. Extend `code_index.storage` with
`verify_index_compat(conn, backend)` so search (and later Phase 6) can
loud-fail on embedding model / dim drift.

```python
# src/code_index/search.py

from dataclasses import dataclass
from pathlib import Path
from typing import Final, Literal
import sqlite3

import numpy as np

from code_index.config import CodeIndexConfig
from code_index.embeddings import EmbeddingBackend

Mode = Literal["bm25", "dense", "hybrid"]

RRF_K: Final[int] = 60
EXCERPT_MAX_LINES: Final[int] = 30


@dataclass(frozen=True)
class SearchResult:
    path: str
    start_line: int
    end_line: int
    language: str
    kind: str
    name: str | None
    scope: str | None
    excerpt: str
    score: float


@dataclass(frozen=True)
class SearchFilters:
    lang: str | None = None
    kind: str | None = None
    path_glob: str | None = None


def search(
    conn: sqlite3.Connection,
    query: str,
    *,
    backend: EmbeddingBackend | None,
    mode: Mode = "hybrid",
    k: int = 20,
    bm25_k: int = 100,
    dense_k: int = 100,
    filters: SearchFilters = SearchFilters(),
) -> list[SearchResult]:
    """Run a search against the open index connection.

    - mode == "bm25": run BM25 only; `backend` may be None.
    - mode == "dense": run dense only; `backend` is required.
    - mode == "hybrid": run both and fuse via RRF; `backend` is required.

    Filters are applied via SQL WHERE on both candidate queries before
    fusion. Returns at most `k` results, ordered by descending fused score.
    Returning an empty list is valid; it is not an error.
    """


def _bm25_candidates(
    conn: sqlite3.Connection,
    query: str,
    *,
    limit: int,
    filters: SearchFilters,
) -> list[tuple[int, int]]:
    """Return (chunk_id, rank) pairs from FTS5 BM25, rank starting at 1.

    SQL shape:
        SELECT c.id
        FROM chunks_fts f JOIN chunks c ON c.id = f.rowid
        WHERE chunks_fts MATCH :q
          [AND c.language = :lang]
          [AND c.kind = :kind]
          [AND c.path GLOB :path]
        ORDER BY bm25(chunks_fts)
        LIMIT :limit
    """


def _dense_candidates(
    conn: sqlite3.Connection,
    query_vector: np.ndarray,
    *,
    limit: int,
    filters: SearchFilters,
) -> list[tuple[int, int]]:
    """Return (chunk_id, rank) pairs from sqlite-vec cosine, rank starting at 1.

    SQL shape (per sqlite-vec MATCH/KNN syntax):
        SELECT e.chunk_id
        FROM embeddings e JOIN chunks c ON c.id = e.chunk_id
        WHERE e.embedding MATCH :qvec
          [AND c.language = :lang]
          [AND c.kind = :kind]
          [AND c.path GLOB :path]
          AND k = :limit
        ORDER BY distance
    """


def _rrf_fuse(
    bm25: list[tuple[int, int]],
    dense: list[tuple[int, int]],
) -> list[tuple[int, float]]:
    """Reciprocal Rank Fusion with k = RRF_K. Returns (chunk_id, score)
    sorted by score descending. Ties broken by rank in the dense list
    (lower dense rank wins). Items present in only one list contribute
    that list's term only.
    """


def _hydrate(
    conn: sqlite3.Connection,
    scored: list[tuple[int, float]],
    *,
    k: int,
) -> list[SearchResult]:
    """Look up the top-k chunk rows by id and return SearchResult instances.
    `excerpt` is the first EXCERPT_MAX_LINES lines of chunks.content.
    """
```

from code_index.embeddings import EmbeddingBackend

def verify_index_compat(
    conn: sqlite3.Connection,
    backend: EmbeddingBackend,
) -> None:
    """Verify meta.embed_model and meta.embed_dim match `backend`.

    - meta.embed_model != backend.name -> CodeIndexError(EXIT_INDEX_MODEL,
      Kinds.INDEX_EMBED_MODEL_MISMATCH, ...).
    - meta.embed_dim != str(backend.dim) -> CodeIndexError(EXIT_INDEX_MODEL,
      Kinds.INDEX_EMBED_DIM_MISMATCH, ...).
    - Missing meta keys -> treat as model mismatch (the index predates the
      embed-model write contract); message prompts for `code_index index rebuild`.
    """

## Tests

`tests/test_search_pipeline.py`:

- **Fixture builder.** A helper `make_index(tmp_path, rows)` that calls
  `open_index(tmp_path / "index.sqlite")`, inserts rows into `chunks`,
  `chunks_fts`, and `embeddings` with deterministic vectors, writes
  `meta.embed_model = "fake:tiny"` and `meta.embed_dim = "4"`, and returns
  the connection. The dim is 4 so test vectors are short and obvious.
  Note: the Phase 1 schema creates `embeddings` with `FLOAT[768]`. The
  test builder reuses `open_index` and accepts whatever dim the schema
  has — see [`001.context.md`](001.context.md) for the synthetic-DB
  strategy (drop+recreate `embeddings` at dim 4 inside the helper).
- **`FakeBackend`.** Tiny in-memory backend with `name = "fake:tiny"`,
  `dim = 4`, and `encode(texts)` returning a deterministic vector per
  input (e.g. one-hot indexed by a per-test mapping).
- `test_bm25_only_returns_token_match` — index contains a chunk whose
  `chunks_fts.content` includes the token `llListenRemove`; `search(...,
  mode="bm25")` for query `"llListenRemove"` returns that chunk first.
- `test_dense_only_returns_nearest_vector` — index contains chunks with
  hand-crafted vectors; `search(..., mode="dense")` for a query mapped
  to a known vector returns the chunk whose stored vector is closest.
- `test_hybrid_fuses_both_pools` — set up a corpus where the lexical
  winner and the dense winner are different chunks; `mode="hybrid"`
  returns a fused list where the lexical and dense winners are both
  present and ranked by fused RRF score.
- `test_rrf_k_constant` — assert `RRF_K == 60` (guards against
  accidental change).
- `test_rrf_tie_break_prefers_dense_rank` — construct two `(chunk_id,
  rank)` lists where two items have identical contributions; assert the
  fused order matches "lower dense rank wins" per `retrieval.md`.
- `test_filter_lang_applied_to_both_pools` — index has chunks tagged
  `language = "python"` and `language = "go"`; `search(..., filters=
  SearchFilters(lang="python"), mode="hybrid")` returns only `python`
  rows.
- `test_filter_kind_applied` — same shape, but `kind="function"` vs
  `kind="class"`.
- `test_filter_path_glob_applied` — same shape, but
  `path_glob="src/foo/*"`.
- `test_zero_results_returns_empty_list` — query that matches nothing
  returns `[]`, does not raise.
- `test_excerpt_truncated_to_30_lines` — chunk content is 100 lines;
  `SearchResult.excerpt` has at most `EXCERPT_MAX_LINES` lines.
- `test_dense_mode_requires_backend` — `search(..., mode="dense",
  backend=None)` raises (ValueError or `CodeIndexError`; coder's call,
  document the choice).
- `test_bm25_mode_accepts_none_backend` — `search(..., mode="bm25",
  backend=None)` succeeds.
- `test_k_limits_returned_rows` — corpus has 50 matching chunks;
  `search(..., k=5)` returns exactly 5.
- `test_bm25_k_caps_candidate_pool` — corpus has 200 BM25 matches;
  `search(..., bm25_k=10, mode="bm25", k=20)` returns at most 10.

## Definition of done

- `src/code_index/search.py` exposes `RRF_K`, `EXCERPT_MAX_LINES`,
  `SearchResult`, `SearchFilters`, `Mode`, and `search(...)` with the
  documented behavior.
- BM25 and dense candidate queries apply `--lang`, `--kind`, `--path`
  filters as SQL `WHERE` clauses on both pools, before fusion.
- RRF fusion uses `k = 60`; tie-break is lower dense rank wins.
- `--mode bm25` does not require a backend; `--mode dense` and
  `--mode hybrid` do.
- `SearchResult.excerpt` is the first `EXCERPT_MAX_LINES` lines of
  `chunks.content`.
- Zero results returns an empty list, does not raise.
- `verify_index_compat(conn, backend)` raises
  `index.embed_model_mismatch` or `index.embed_dim_mismatch` (code 11)
  on drift; returns None on match; missing meta is treated as a model
  mismatch with a rebuild-prompting message.
- `uv run pytest tests/test_search_pipeline.py tests/test_storage_compat.py`
  passes.
- `uv run ruff check` passes.
- `uv run pyright` passes.
