# Step 001 — Fastembed backend

## Goal

Create the `code_index.embeddings` package, define the `EmbeddingBackend` Protocol, and implement `FastembedBackend` with the batching loop. Cover correctness and cache-reuse via real-download integration tests against a gitignored test cache.

## Files

- `src/code_index/embeddings/__init__.py` (new)
- `src/code_index/embeddings/protocol.py` (new)
- `src/code_index/embeddings/fastembed.py` (new)
- `tests/test_fastembed_backend.py` (new)
- `.gitignore` (edit — add `tests/.cache/` if not already present; this folder is the persistent fastembed model cache and must survive across `uv run pytest` invocations)

import numpy as np

@runtime_checkable
class EmbeddingBackend(Protocol):

    dim: int             # vector dimension, e.g. 768

    def encode(self, texts: list[str]) -> np.ndarray:
        """Return embeddings of shape (len(texts), dim)."""
        ...

```python
# src/code_index/embeddings/fastembed.py

import numpy as np

class FastembedBackend:
    name: str
    dim: int

    def __init__(
        self,
        model: str,
        batch_size: int = 32,
        cache_dir: str | None = None,
    ) -> None:
        """Instantiate a fastembed text-embedding model.

        model      — fastembed model identifier (e.g. "jinaai/jina-embeddings-v2-base-code").
        batch_size — how many texts to pass per encode call to fastembed.
        cache_dir  — where fastembed stores downloaded ONNX files. None → library default.
        """

    def encode(self, texts: list[str]) -> np.ndarray:
        """Encode `texts` in batches of `self._batch_size`. Returns ndarray of
        shape (len(texts), self.dim). Empty input returns shape (0, self.dim)."""
```

```python
# src/code_index/embeddings/__init__.py

from .protocol import EmbeddingBackend
from .fastembed import FastembedBackend

__all__ = ["EmbeddingBackend", "FastembedBackend"]
```

`name` format: `"fastembed:<short-name>"`, where `<short-name>` is a stable shortening of the model identifier. For the default `"jinaai/jina-embeddings-v2-base-code"`, name is `"fastembed:jina-code-v2"` to match the example in [`../../architecture/embeddings.md`](../../architecture/embeddings.md). For other models, derive a short name from the model identifier (coder picks a deterministic rule; document it in `001.context.md`).

`dim` is read from the underlying fastembed model after instantiation — do not hardcode 768. Tests assert it equals 768 for the default model.

## Tests

`tests/test_fastembed_backend.py` — real-download integration tests against the persistent gitignored cache at `tests/.cache/fastembed/`.

The file defines one session-scoped fixture `default_backend` that instantiates `FastembedBackend("jinaai/jina-embeddings-v2-base-code", cache_dir="tests/.cache/fastembed")` exactly once per pytest session and yields it. All tests below that need a working backend take this fixture rather than constructing their own — within a single `uv run pytest` run the default model is loaded into memory at most once. The fixture must not delete or clean the cache directory at setup or teardown.

- `test_encode_shape(default_backend)`: `result = default_backend.encode(["foo", "bar"])`; assert `result.shape == (2, default_backend.dim)` and `default_backend.dim == 768`.
- `test_encode_single_under_batch(default_backend)`: encode `["only-one"]`; assert shape `(1, 768)`.
- `test_encode_multi_batch`: needs `batch_size=4`, which differs from the default. The coder picks one of:
  (a) parametrize the shared fixture,
  (b) instantiate a second `FastembedBackend` with the same `cache_dir` (skips download but loads the model a second time),
  (c) accept that this is the one test that pays a second model-load cost.
  Document the choice in `001.context.md`. The test must assert shape `(11, 768)` for `2 * 4 + 3 == 11` strings AND that the first 4 rows match a separate `encode([...first4...])` call (within float tolerance).
- `test_encode_empty_input(default_backend)`: `default_backend.encode([])` returns shape `(0, default_backend.dim)`.
- `test_cache_directory_populated(default_backend)`: after the fixture has run, `tests/.cache/fastembed/` exists and is non-empty.
- `test_second_instantiation_reuses_cache`: this is the one test that **must instantiate a fresh `FastembedBackend`** to verify cold-cache behavior. After the session fixture has populated the cache, snapshot the directory (file count + total byte size, or a sorted list of `(relpath, size)` tuples). Instantiate a fresh `FastembedBackend("jinaai/jina-embeddings-v2-base-code", cache_dir="tests/.cache/fastembed")`. Snapshot again. Assert the two snapshots are identical (no new files, no size change). Drop the fresh backend reference at end of test.
- `test_name_format(default_backend)`: `default_backend.name == "fastembed:jina-code-v2"`.
- `test_satisfies_protocol(default_backend)`: `isinstance(default_backend, EmbeddingBackend)` is `True` (relies on `@runtime_checkable`). Also acts as a structural-typing smoke check for pyright.

## Definition of done

- `src/code_index/embeddings/` package exists with `__init__.py`, `protocol.py`, `fastembed.py`.
- `EmbeddingBackend` Protocol carries exactly the attributes/method named above; decorated `@runtime_checkable`.
- `FastembedBackend.__init__` accepts `model`, `batch_size`, `cache_dir` with the documented defaults.
- `FastembedBackend.encode` batches `texts` per `batch_size`, concatenates outputs along axis 0, and returns shape `(len(texts), dim)`. Empty input returns `(0, dim)`.
- `FastembedBackend.dim` is read from the underlying model (not hardcoded) and equals `768` for the default model.
- `FastembedBackend.name` follows `"fastembed:<short-name>"`; the default model maps to `"fastembed:jina-code-v2"`.
- First instantiation downloads to `tests/.cache/fastembed/`; the cache-reuse test confirms a fresh instantiation against the populated cache does not change the directory contents (no new files, no size change).
- Cache directory `tests/.cache/fastembed/` is created on first test run and is never deleted by test code (no fixture, no teardown, no autouse cleanup touches it). Subsequent `uv run pytest` invocations on the same machine do not re-download the model.
- Within a single `uv run pytest` run the default model loads into memory at most once — exactly one `FastembedBackend(...)` for the default model lives in the session fixture. The batching test may load a second instance only if option (b) of the three choices above is taken; the cache-reuse test loads one extra fresh instance by design.
- `.gitignore` covers `tests/.cache/` (or a parent path that includes it).
- `uv run pytest tests/test_fastembed_backend.py` passes (first run downloads ~120MB; subsequent runs are fast and offline-capable).
- `uv run pyright` passes — `FastembedBackend` satisfies `EmbeddingBackend` structurally without inheritance.
- `uv run ruff check` passes.
