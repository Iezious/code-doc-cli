# 005 — context

Narrow notes for the cross-subcommand DoD step. Feature-wide framing is in [`context.md`](context.md); each subcommand's pinned JSON shape lives in its originating phase's plan and is summarized in `context.md` "Prior-phase artifacts this phase consumes".

## Session-fixture strategy

Phase 5's `005.search/002.context.md` "Session-fixture model-cache reuse" describes the pattern: a session-scoped pytest fixture copies the polyglot fixture, runs `init` + `index build` once, and yields the path. Step 005 reuses the same idea:

```python
@pytest.fixture(scope="session")
def built_project(tmp_path_factory):
    src = pathlib.Path("tests/fixtures/projects/polyglot_minimal").resolve()
    dst = tmp_path_factory.mktemp("polyglot_built")
    shutil.copytree(src, dst, dirs_exist_ok=True)
    # init + index build via CliRunner inside this fixture
    ...
    return dst
```

Tests that mutate the index (sync after edit, schema-mismatch carve-out, model-mismatch failure) copy `built_project` to a function-scoped `tmp_path` first.

Tests that do not mutate (`search`, `symbols`, `graph` happy paths; `config show` happy path) `monkeypatch.chdir(built_project)` directly and run read-only queries.

## Fastembed model cache reuse

The session fixture runs a real `index build`, which downloads the fastembed model on first invocation. Per Phase 2's contract (`002.embedding-backend/context.md` decision 2), the cache lives in `tests/.cache/fastembed/` and is gitignored. Step 005's tests reuse the same cache directory by setting whatever env var Phase 2 used (`FASTEMBED_CACHE_DIR` or equivalent — confirm by reading `tests/test_fastembed_backend.py` at coding time).

If the cache var is not set, fastembed's library default applies, which downloads to the user's home directory. Acceptable as a fallback but slow on CI.

## "Failure path" definition

For each subcommand, "failure path" means: invoke the subcommand under a condition that produces a non-zero exit code under `--format json`. The DoD test asserts:

1. `json.loads(result.stdout)` succeeds.
2. The parsed document has shape `{"error": {"code": int, "kind": str, "message": str, "detail": ...}}`.
3. `error.code == result.exit_code`.
4. `error.kind` is one of the documented strings for that failure mode (per the table in `005.json-roundtrip-dod.md`).
5. `error.message` is a non-empty string. Do NOT assert message text content — per `errors-and-exit-codes.md` "Implications": "Agents must not regex-match `message`."

## Multi-failure subcommands

Some subcommands have multiple failure modes (e.g. `index sync` can fail on missing index, model mismatch, schema mismatch, missing config). The DoD test exercises **at least one** per the Phase 7 DoD wording ("the same subcommands under failure conditions emit a parseable error envelope"). Step 005 picks the most representative one per the table in `005.json-roundtrip-dod.md`; other failure modes are covered by per-phase tests (Phase 6's symbols/graph tests, Phase 5's search tests, etc.).

## `graph deps`'s `meta` field

Per `context.md` decision 7, `meta` stays a JSON string (not re-parsed). The DoD assertion is structural only: `result["meta"]` is either `None` or a `str`. The test does not call `json.loads(result["meta"])` to validate the inner contents.

## "Inline-documented contract" definition

The Phase 7 DoD says shapes are "documented inline per subcommand". Step 005's test parametric table is the operational form of "inline documentation" — each subcommand's expected top-level keys are listed in code. The `outcome.md` candidate items propose that the architect fold the same shape definitions into `cli.md` per-subcommand sections. Until the architect applies that fold-in, the test file is the de facto contract.

## Why session-scope for `built_project`

Running real `index build` costs ~5-15 seconds per invocation (embedding 7 source files). The 10+ success-path tests in this file all need a built index; running build per-test is 60-150 seconds of overhead. Session-scope brings it to one build per `pytest` invocation.

For tests that mutate (sync after edit, schema-mismatch carve-out), function-scope is required — the session-scoped tree must not be mutated. Use `shutil.copytree(built_project, tmp_path, dirs_exist_ok=True)` in the mutation tests' setup.

## What this step does NOT do

- Does not modify any production code.
- Does not test the `--format text` paths exhaustively. Text-mode is covered by each subcommand's per-phase tests.
- Does not test backend wrapping failure paths directly — step 003's tests cover those.
- Does not test the boundary exception handler itself — Phase 1's tests cover that.
- Does not test `--format json` shapes that differ from what each phase pinned. If a shape mismatch surfaces, file an observation in `outcome.md` for the architect; do NOT change the production shape in this step.
- Does not test Voyage backend paths (out of scope per `context.md`).
