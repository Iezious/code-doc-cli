# Step 003 — fastembed backend exception wrapping

## Goal

Wrap native fastembed exceptions raised from `FastembedBackend.__init__`, `FastembedBackend.encode`, and `from_config` in `CodeIndexError` with the registered backend kinds. Make `backend.model_download_failed` (code 20) and `backend.encode_failed` (code 20) producible from the engine — they are already in the Phase 1 `Kinds` registry but have no producer until now.

## Files to create or modify

- `src/code_index/embeddings/fastembed.py` (edit — wrap `__init__` and `encode`)
- `src/code_index/embeddings/factory.py` (edit — wrap `from_config`'s `FastembedBackend(...)` call)
- `tests/test_backend_init_wrapping.py` (new)

## Signatures

Public signatures of the three call sites do not change; the bodies grow try/except shells. From Phase 2 (`002.embedding-backend/context.md`):

```python
# src/code_index/embeddings/protocol.py — unchanged
class EmbeddingBackend(Protocol):
    name: str
    dim: int
    def encode(self, texts: list[str]) -> np.ndarray: ...

# src/code_index/embeddings/fastembed.py — bodies wrapped
class FastembedBackend:
    name: str
    dim: int
    def __init__(self, model: str, batch_size: int) -> None: ...
    def encode(self, texts: list[str]) -> np.ndarray: ...

# src/code_index/embeddings/factory.py — body wrapped
def from_config(config: CodeIndexConfig) -> EmbeddingBackend: ...
```

Wrapping behavior:

- `FastembedBackend.__init__`: wrap the fastembed library call (typically `TextEmbedding(model_name=...)` instantiation, plus any model-download / cache-directory work the constructor triggers) in `try/except Exception as exc`. Re-raise as `CodeIndexError(EXIT_BACKEND, Kinds.BACKEND_MODEL_DOWNLOAD_FAILED, f"fastembed model '{model}' failed to load: {exc}", {"model": model, "cause": str(exc), "type": type(exc).__name__}) from exc`. Catch `Exception`, not `BaseException` — `KeyboardInterrupt` and `SystemExit` should still propagate.
- `FastembedBackend.encode`: wrap the inner `self._model.embed(batch)` (or equivalent) call in `try/except Exception as exc`. Re-raise as `CodeIndexError(EXIT_BACKEND, Kinds.BACKEND_ENCODE_FAILED, f"fastembed encode failed: {exc}", {"model": self.name, "cause": str(exc), "type": type(exc).__name__, "batch_size": len(batch_or_full_texts)}) from exc`. The wrap is around the actual fastembed call inside the batching loop, not around the entire `encode` method — `CodeIndexError` itself is allowed to propagate cleanly without being re-wrapped.
- `from_config`: wrap the `FastembedBackend(model=..., batch_size=...)` constructor call. If `__init__` already wraps and re-raises a `CodeIndexError`, the factory's wrap is a no-op pass-through for `CodeIndexError`. The factory's wrap exists to catch exceptions raised by intermediate factory logic (e.g. config-reading sub-paths that surface a native fastembed exception before the constructor is called) — in MVP, this collapses to "let `CodeIndexError` propagate, wrap anything else as `BACKEND_MODEL_DOWNLOAD_FAILED`".

The Voyage stub from Phase 2 (raises `CodeIndexError(EXIT_USAGE, Kinds.CLI_NOT_IMPLEMENTED, ...)`) is untouched — it already raises a `CodeIndexError`, so the new wrap layer is a pass-through for it.

## Tests

`tests/test_backend_init_wrapping.py` uses `monkeypatch` to replace the fastembed library entry point (`fastembed.TextEmbedding` or whichever Phase 2 actually imports — confirm by reading `embeddings/fastembed.py` at coding time). Cases:

- **Model download failure wraps to `BACKEND_MODEL_DOWNLOAD_FAILED`.** `monkeypatch` `fastembed.TextEmbedding.__init__` to raise `RuntimeError("simulated download failure")`. Call `FastembedBackend(model="jinaai/jina-embeddings-v2-base-code", batch_size=32)`. Assert `CodeIndexError` is raised, `err.code == EXIT_BACKEND` (20), `err.kind == "backend.model_download_failed"`, `err.detail["cause"]` contains `"simulated download failure"`, `err.detail["type"] == "RuntimeError"`.
- **`from_config` wraps the constructor.** `monkeypatch` `FastembedBackend.__init__` to raise `RuntimeError("...")`. Build a `CodeIndexConfig` with `embed_backend="fastembed"`. Call `from_config(config)`. Assert same `CodeIndexError` semantics as above.
- **Encode failure wraps to `BACKEND_ENCODE_FAILED`.** Construct a real `FastembedBackend` (or `monkeypatch` `FastembedBackend.__init__` to a no-op so this test does not depend on the cache). Then `monkeypatch` `backend._model.embed` (or the equivalent inner call) to raise `ValueError("simulated encode failure")`. Call `backend.encode(["hello", "world"])`. Assert `CodeIndexError` raised, `err.code == EXIT_BACKEND`, `err.kind == "backend.encode_failed"`, `err.detail["cause"]` contains `"simulated encode failure"`.
- **`CodeIndexError` is not re-wrapped.** Construct a `FastembedBackend` whose `encode` inner call raises `CodeIndexError(EXIT_BACKEND, Kinds.BACKEND_ENCODE_FAILED, "already wrapped")` directly. Call `backend.encode(...)`. Assert the same `CodeIndexError` instance propagates unchanged (no double-wrap, no re-raise with a different message). Identity check: `pytest.raises(CodeIndexError) as exc_info; assert exc_info.value.message == "already wrapped"`.
- **`from exc` chaining preserved.** For the model-download case, assert `err.__cause__` is the original `RuntimeError` (preserved by `raise ... from exc`).
- **JSON envelope round-trip on a wrapped failure.** Catch the `CodeIndexError`, call `err.envelope()`, then `json.dumps(...)` it, then `json.loads(...)` it. Assert the round-trip dict has `error.code == 20` and `error.kind == "backend.model_download_failed"` (or `"backend.encode_failed"` for the encode case). Verifies the envelope writer's output round-trips through `json.loads` — a Phase 7 DoD precondition.

## Definition of done

- `FastembedBackend.__init__` exceptions are wrapped in `CodeIndexError(EXIT_BACKEND, Kinds.BACKEND_MODEL_DOWNLOAD_FAILED, ...)`.
- `FastembedBackend.encode` exceptions are wrapped in `CodeIndexError(EXIT_BACKEND, Kinds.BACKEND_ENCODE_FAILED, ...)`.
- `from_config` wraps `FastembedBackend(...)` construction errors the same way as `__init__`.
- `CodeIndexError` instances raised inside the wrapped region propagate without being re-wrapped.
- `raise ... from exc` chaining is preserved.
- The error envelope produced by a wrapped failure round-trips through `json.loads`.
- All cases in `tests/test_backend_init_wrapping.py` pass.
- `uv run pytest tests/test_backend_init_wrapping.py` passes.
- `uv run ruff check src/code_index/embeddings/ tests/test_backend_init_wrapping.py` passes.
- `uv run pyright` passes.
