# Step 005 — cross-subcommand JSON round-trip DoD

## Goal

Tests-only step. Enumerate every MVP subcommand, assert that:

1. Each subcommand's `--format json` stdout on the success path round-trips through `json.loads` and matches the inline-documented shape.
2. At least one failure mode per subcommand emits a parseable error envelope with the expected `code` and `kind`.

This is the Phase 7 DoD operationalized.

## Files to create or modify

- `tests/test_json_roundtrip_dod.py` (new)
- No production code changes.

## Signatures

No production signatures change. The test file is self-contained.

Test fixtures reused from prior phases:

- `tests/fixtures/projects/polyglot_minimal/` (Phase 4) — copied to `tmp_path` per test (or once per session for the read-only success cases).
- `tests/fixtures/config_valid.toml` (Phase 1) — reused for `config show` against a hand-written config without an index.

## Tests

`tests/test_json_roundtrip_dod.py` uses `typer.testing.CliRunner` with `monkeypatch.chdir`. A session-scoped fixture (`built_project`) copies the polyglot fixture, runs `code_index init` + `code_index index build` once, and yields the path. Per-test fixtures may copy that built tree to a function-scoped `tmp_path` when mutation is needed.

The test file is organized into one test per subcommand plus a "shapes-table" parametric test.

### Subcommands to cover

The full MVP subcommand list from `cli.md`:

| Subcommand | Success-path test | Failure-path test |
|---|---|---|
| `init` | Fresh init in empty `tmp_path` | Refuse without `--force` against populated dir |
| `index build` | Build against polyglot fixture | Missing `docs/.helpers/config.toml` (no `init`) |
| `index sync` | Sync after edit | Model mismatch (`meta.embed_model` manually corrupted) |

| `symbols defs` | `symbols defs <known-name>` | Missing index (no `index build` yet) |
| `symbols refs` | `symbols refs <known-name>` | Same — missing index |
| `graph callers` | `graph callers <known-name>` | Same |
| `graph deps` | `graph deps <known-path>` | Same |
| `config show` | `config show` after build | Missing config (Phase 7 carve-out: schema mismatch still exits 0, so the failure-path test for `config show` is "no config discovered") |

### Per-subcommand assertions (success path)

For each subcommand's success-path test:

1. Set up the necessary preconditions (use `built_project` fixture or a fresh `tmp_path`).
2. `result = runner.invoke(app, [...subcommand-args..., "--format", "json"])`.
3. Assert `result.exit_code == 0`.
4. Assert `parsed = json.loads(result.stdout)` succeeds — does not raise.
5. Assert the shape matches `context.md`'s pinned contract for that subcommand. Concretely, the test parametric table lists `(subcommand, expected_top_level_keys_or_type)`:
   - `init`: dict with keys `{"config_path", "gitignore_path", "project", "force_used"}`.
   - `index build`: dict with keys `{"files_walked", "files_chunked", "chunks_inserted", "symbols_inserted", "edges_inserted", "seconds_elapsed"}`.
   - `index sync`: dict with keys `{"files_added", "files_changed", "files_unchanged", "files_removed", "chunks_inserted_total", "seconds_elapsed"}`.
   - `index rebuild`: dict with keys matching `index build` (per Phase 6 decision).
   - `search`: dict with key `{"results"}` mapping to a list.
   - `symbols defs` / `symbols refs`: list of dicts each with keys `{"path", "scope", "language", "name", "line"}`.
   - `graph callers`: list of dicts each with keys `{"path", "scope", "language", "start_line", "kind", "dst_name"}`.
   - `graph deps`: list of dicts each with keys `{"path", "kind", "dst_name", "meta"}`.
   - `config show`: dict with keys `{"config", "index"}`; `config` is a dict, `index` is either a dict or `null`.

### Per-subcommand assertions (failure path)

For each subcommand's failure-path test:

1. Set up the failure condition (most cases: omit `init` so the config / index is absent; for `--mode garbage` etc., pass bad args).
2. `result = runner.invoke(app, [...subcommand-args..., "--format", "json"])`.
3. Assert `result.exit_code != 0`.
4. Assert `parsed = json.loads(result.stdout)` succeeds.
5. Assert `parsed["error"]["code"] == result.exit_code`.
6. Assert `parsed["error"]["kind"]` is one of the documented strings for that failure mode:
   - `init` refuse-without-force: whatever Phase 4 pinned (do not assert specific kind; just structural `{"error": {...}}` and round-trip).
   - `index build` missing config: `Kinds.INDEX_MISSING` (`"index.missing"`).
   - `index sync` model mismatch: `Kinds.INDEX_EMBED_MODEL_MISMATCH` (`"index.embed_model_mismatch"`).
   - `index rebuild` missing `--yes`: `Kinds.USAGE_CONFIRMATION_REQUIRED` (`"usage.confirmation_required"`).
   - `search --mode garbage`: `Kinds.CLI_BAD_ENUM` (`"cli.bad_enum"`).
   - `symbols defs/refs` missing index: `Kinds.INDEX_MISSING` (`"index.missing"`).
   - `graph callers/deps` missing index: `Kinds.INDEX_MISSING` (`"index.missing"`).
   - `config show` missing config: `Kinds.INDEX_MISSING` (`"index.missing"`). (Per Phase 1's reuse rationale — `index.missing` covers both "no config" and "no index file" with different messages.)

7. Assert `parsed["error"]["message"]` is a non-empty string (do not assert on text content per `errors-and-exit-codes.md` "Implications": "The contract intentionally does not promise message text stability").

### "Zero-results is not an error" assertion

For `search`, `symbols defs`, `symbols refs`, `graph callers`, `graph deps`: also assert that an empty-result success path round-trips through `json.loads`. E.g. `search xyznevermatches` returns `{"results": []}` with exit 0; `symbols defs zzz_nope` returns `[]` with exit 0. This catches the case where a subcommand emits nothing on zero results, breaking `json.loads`.

### `config show` schema-mismatch carve-out

A dedicated assertion: after build, mutate `meta.schema_version` to `"99"`, run `config show --format json`, assert exit 0 and `json.loads(stdout)["index"]["schema_version"] == "99"`. This is the diagnostic carve-out from step 001 re-asserted at the DoD level.

## Definition of done

- `tests/test_json_roundtrip_dod.py` exists and covers every MVP subcommand from `cli.md`.
- Each subcommand has at least one success-path test and at least one failure-path test, both asserting `json.loads(result.stdout)` succeeds.
- Each failure-path test asserts the expected `kind` string per the table above.
- The "zero-results round-trips" test passes for every result-list subcommand.
- The "`config show` does not gate on schema mismatch" assertion passes.
- `uv run pytest tests/test_json_roundtrip_dod.py` passes.
- `uv run pytest` (full suite) passes — this is the phase-level gate.
- `uv run ruff check tests/test_json_roundtrip_dod.py` passes.
- `uv run pyright` passes.
- Phase 7 DoD from `mvp-phases.md` is satisfied: "every MVP subcommand under `--format json` round-trips through `json.loads`; the same subcommands under failure conditions emit a parseable error envelope."
