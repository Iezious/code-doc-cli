# 001 — context

Narrow notes for the `config show` step. Feature-wide framing is in [`context.md`](context.md).

## Diagnostic-open mechanism

Phase 1's `open_index(db_path, *, create_if_missing=True, check_version=True)` raises `Kinds.INDEX_SCHEMA_MISMATCH` (code 10) when `meta.schema_version` does not match the engine's expected version. `config show` is the only subcommand that must read `meta` despite a possible schema mismatch.

Two options for the diagnostic read; either is acceptable:

1. **Pass `check_version=False` to `open_index`.** The cleanest path if Phase 1's helper exposes it (per `001.foundations/004.storage.md` and `006.sync-symbols-graph/context.md` line 64, the signature is `open_index(db_path, *, create_if_missing=True, check_version=True)`). Set `check_version=False, create_if_missing=False` to read meta without creating a fresh DB and without raising on schema drift.
2. **Hand-roll a `sqlite3.connect(...)` + `SELECT value FROM meta WHERE key = ?`** inside `_read_index_meta`. Avoids Phase 1 helper coupling but duplicates a tiny bit of SQL. Acceptable if option 1 produces a corner-case raise (e.g. missing `meta` table because the file is empty).

Prefer option 1. If a test demonstrates option 1 still raises, fall back to option 2 and note it in `outcome.md`.

## File-existence check

`_read_index_meta(db_path)` checks `db_path.exists()` first. Returns `None` when the file is absent. Do **not** rely on `open_index(create_if_missing=False)` raising for the missing case — the diagnostic-read semantics want a clean `None`, not an exception we then suppress.

## `Kinds.INDEX_UNREADABLE` for the corrupt-file case

The "index file present but unparseable" case is the only failure `config show` raises on a meta read. The kind `index.unreadable` is already registered in Phase 1 (`Kinds.INDEX_UNREADABLE = "index.unreadable"`, code 10 per `errors-and-exit-codes.md` "Index/storage (codes 10, 12)" section). Reuse it. Trigger detection: catch `sqlite3.DatabaseError` (raised by `sqlite3.connect` or the first query against a non-SQLite file) and translate to `CodeIndexError(EXIT_INDEX_SCHEMA, Kinds.INDEX_UNREADABLE, ...)`.

## Text-mode formatting

Phase 1 used "one `key = value` per line, sorted by key" (per `001.foundations/005.cli.md` line 76). Phase 7 extends to two blocks. Suggested format:

```
config:
  config_path: /abs/.../docs/.helpers/config.toml
  embed_backend: fastembed
  embed_batch_size: 32
  embed_model: jinaai/jina-embeddings-v2-base-code
  ...
  version: >=0.3,<0.5

index:
  schema_version: 1
  code_index_version: 0.3.0
  embed_model: jinaai/jina-embeddings-v2-base-code
  embed_dim: 768
```

Or, when no index file exists:

```
config:
  ...

index: not built
```

The exact prose is the coder's call as long as both blocks are distinguishable, sorted-by-key inside each block, and a missing index reads as `not built` rather than as an empty block.

The optional `[mismatch]` marker (decision 1 in `context.md`) is text-mode only; JSON consumers compare the two `embed_model` strings themselves.

## Path resolution

`db_path` is `config.project_root / "docs" / ".helpers" / "index.sqlite"`. The `project_root` field is computed by the Phase 1 config loader as the parent directory of the discovered `config.toml`. Phase 4's `init` and `indexer.build` write to the same location, so the path is consistent across phases.

## JSON key ordering

`json.dumps(..., sort_keys=False)` preserves insertion order. The `"config"` block follows Phase 1's pin (see `001.foundations/005.context.md` lines 53–69). The `"index"` block emits `schema_version, code_index_version, embed_model, embed_dim` in that order. The two top-level keys are `"config"` then `"index"`.

## Why no schema gating

This is the carve-out that distinguishes `config show` from every other subcommand. Every other Phase 5/6 subcommand uses `open_index(check_version=True)` and the embedding-compat helper to gate on schema and model drift (per `006/context.md` decision 7 and `005/context.md` "Cross-cutting constraints"). `config show` is the diagnostic tool the user invokes precisely to see drift — making it refuse on drift would be hostile.

The carve-out is documented in `context.md` decision 1 and is the subject of one of the `outcome.md` candidate items.

## What this step does NOT do

- Does not modify `errors.py`, `embeddings/`, or any module other than `cli.py`.
- Does not modify the `"config"` block's shape. Phase 1's pin (sorted by key inside, specific key names) is preserved.
- Does not add `meta` keys beyond the four `storage.md` enumerates.
