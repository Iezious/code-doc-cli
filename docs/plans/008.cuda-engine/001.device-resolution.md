# Step 001 — Device resolution helper

## Goal

Add a new `src/code_index/embeddings/device.py` module that reads and validates `CODE_INDEX_DEVICE`, probes onnxruntime providers, resolves to `cpu`/`cuda`, and emits the clean stderr warning when `cuda` was requested but unavailable.

## Files to create or modify

- `src/code_index/embeddings/device.py` (create)
- `tests/test_device_resolution.py` (create)

## Signatures

```python
# src/code_index/embeddings/device.py

DEVICE_ENV_VAR: str = "CODE_INDEX_DEVICE"
VALID_DEVICES: tuple[str, ...] = ("auto", "cpu", "cuda")
CUDA_PROVIDER: str = "CUDAExecutionProvider"


def requested_device() -> str:
    """Return the raw CODE_INDEX_DEVICE value (auto|cpu|cuda), 'auto' if unset.
    No probe. Invalid values raise CodeIndexError (see context for kind/code)."""


def available_providers() -> list[str]:
    """Return onnxruntime.get_available_providers(); [] if onnxruntime is
    missing or the call raises (diagnostic stance, never propagates)."""


def cuda_available() -> bool:
    """True iff CUDA_PROVIDER is in available_providers()."""


def resolve_device(requested: str | None = None, *, warn: bool = True) -> str:
    """Resolve requested (default: requested_device()) to 'cpu' or 'cuda'.
    auto -> cuda if cuda_available() else cpu (silent).
    cuda -> cuda if cuda_available() else cpu; when falling back and warn,
            emit a single clean stderr warning.
    cpu  -> cpu."""
```

## Tests

In `tests/test_device_resolution.py`, monkeypatching `os.environ` and the module's onnxruntime probe (patch `available_providers` or the underlying `onnxruntime.get_available_providers`) — no real GPU:

- `requested_device()` returns `auto` when env unset; returns the set value for `cpu`/`cuda`/`auto`; raises `CodeIndexError` (validation kind) on an invalid value (e.g. `gpu`).
- `cuda_available()` True when probe returns a list containing `CUDAExecutionProvider`, False otherwise.
- `available_providers()` returns `[]` (does not raise) when the probe raises / onnxruntime import fails.
- `resolve_device("auto")` → `cuda` when available, `cpu` when not; no stderr output in either case (capture stderr, assert empty).
- `resolve_device("cuda")` → `cuda` when available with no warning; → `cpu` with a single stderr warning when unavailable; `warn=False` suppresses the warning but still returns `cpu`.
- `resolve_device("cpu")` → `cpu` regardless of probe; no warning.

## Definition of done

- `device.py` exposes `requested_device`, `available_providers`, `cuda_available`, `resolve_device`, and the module constants above.
- Invalid `CODE_INDEX_DEVICE` raises `CodeIndexError` with a config-validation kind/code (see `001.context.md`); valid values and unset behave per pinned semantics.
- The onnxruntime probe is isolated so a missing/broken onnxruntime never raises out of `available_providers`/`cuda_available`/`resolve_device`.
- `auto` resolution is silent; `cuda`-unavailable fallback writes exactly one warning to stderr (suppressible with `warn=False`); `cpu` is unconditional and silent.
- New tests pass; `uv run ruff check`, `uv run ruff format`, `uv run pyright` clean.
