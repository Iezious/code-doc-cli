## Why no schema bump

`meta.embed_device` is one additive row in the generic `meta(key TEXT, value TEXT)` KV table. Pre-feature indices simply lack the row (rendered as null/"" by readers). The `meta` store is schema-stable; a new optional KV key is forward-compatible and does not change any table definition. See [storage.md](../../architecture/storage.md), "Update 2026-05-28: device provenance and unknown-engine detection" — the schema sketch comment already lists `embed_device (informational)` in the `meta` row, confirming it is part of the existing schema's intent, not a new versioned structure.
