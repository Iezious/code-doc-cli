## Diagnostic stance is mandatory

`config show` is the FIRST command to instantiate a provider probe. It must NEVER fail or warn because of device resolution:

- `requested_device` uses `requested_device()` — no probe at all, always safe. (An invalid `CODE_INDEX_DEVICE` value still raises per step 001; that is correct — a malformed env var is a real config error, code 2, and is consistent with `config show`'s stance of reporting config issues. The coder should confirm whether `config show` should swallow even that; the cli.md contract says `requested_device` is "one of auto|cpu|cuda, defaulting to auto when unset" — it assumes a valid value. Treat an invalid value as a normal validation error, not a special diagnostic swallow.)
- `effective_device` uses `resolve_device(warn=False)` — the quiet probe. Step 001 already guarantees `available_providers` returns `[]` on a broken/missing onnxruntime, so resolution degrades to `cpu` without raising and without warning. Do not add a separate try/except here beyond what step 001 guarantees.
