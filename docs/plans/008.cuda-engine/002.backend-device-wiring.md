# Step 002 — FastembedBackend device wiring

## Goal

Make `FastembedBackend` accept and resolve a device, pass the corresponding provider/`cuda` flag to fastembed's `TextEmbedding`, expose the resolved device as `self.device`, add `device` to the `EmbeddingBackend` Protocol, and have the factory read the env and pass it through.

## Files to create or modify

- `src/code_index/embeddings/protocol.py` (modify — add `device` attribute)
- `src/code_index/embeddings/fastembed.py` (modify — accept device, resolve, pass to TextEmbedding, set `self.device`)
- `src/code_index/embeddings/factory.py` (modify — read env, pass device to `FastembedBackend`)
- `tests/test_backend_init_wrapping.py` (modify — assert device-arg construction and provider-probe behavior)
- `tests/test_embedding_factory.py` (modify — assert factory passes resolved device)

## Signatures

```python
# protocol.py — EmbeddingBackend Protocol gains:
class EmbeddingBackend(Protocol):
    name: str
    dim: int
    device: str          # informational: resolved 'cpu' | 'cuda'
    def encode(self, texts: list[str]) -> np.ndarray: ...

# fastembed.py
class FastembedBackend:
    name: str
    dim: int
    device: str

    def __init__(
        self,
        model: str,
        batch_size: int = 16,
        cache_dir: str | None = None,
        device: str | None = None,   # raw auto|cpu|cuda; None -> resolve from env
    ) -> None: ...

# factory.py — from_config unchanged signature; fastembed branch now resolves device.
def from_config(config) -> EmbeddingBackend: ...
```

## Tests

In `tests/test_backend_init_wrapping.py` (mirror the existing harness that monkeypatches `code_index.embeddings.fastembed.TextEmbedding` and `FastembedBackend.__init__`):

- When the resolved device is `cuda`, `TextEmbedding` is constructed with the CUDA provider / `cuda=True` (assert on the kwargs captured by the monkeypatched `TextEmbedding`), and `backend.device == "cuda"`.
- When the resolved device is `cpu`, `TextEmbedding` is constructed without the CUDA provider, and `backend.device == "cpu"`.
- `device="cuda"` with the provider unavailable (monkeypatched probe) → backend constructs on CPU, `backend.device == "cpu"`, one stderr warning emitted (the helper's warning, `warn=True` path).
- Native construction failures still wrap as `BACKEND_MODEL_DOWNLOAD_FAILED` (existing behavior preserved).

In `tests/test_embedding_factory.py`:

- `from_config` with `CODE_INDEX_DEVICE` set (monkeypatched env + probe) produces a backend whose `device` matches the resolved value.
- `from_config` still passes `embed_model` and `embed_batch_size` as today.

In `tests/test_fastembed_backend.py` (real `default_backend` fixture): `test_satisfies_protocol` still passes with the Protocol's new `device` attribute (the real backend now sets `self.device`).

## Definition of done

- `EmbeddingBackend` Protocol declares `device: str`; `@runtime_checkable` semantics preserved; existing protocol-satisfaction test passes.
- `FastembedBackend.__init__` accepts `device`; `None` resolves from env via step 001's `resolve_device(warn=True)`; an explicit value resolves the same way.
- The resolved device drives the `TextEmbedding` constructor kwargs (CUDA provider / `cuda=True` for `cuda`; CPU otherwise) and is stored as `self.device`.
- `self.name`, `self.dim`, the tokenizer-truncation override, and the `BACKEND_MODEL_DOWNLOAD_FAILED` wrapping are unchanged.
- `from_config` reads the env via step 001 and passes the device through; no new config key is read.
- New/updated tests pass; `uv run ruff check`, `uv run ruff format`, `uv run pyright` clean.
